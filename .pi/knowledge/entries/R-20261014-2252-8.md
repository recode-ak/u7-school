# Проектирование собственного формата сериализации без потери типов
## Симптомы
Стандартный CSV теряет типы данных (строка '25' и число 25 выглядят одинаково), а стандартный JSON громоздкий для табличных структур.

## Решение
Использовать гибридный подход («велосипед»): табличная структура строк и колонок по аналогии с CSV для компактности, но запись самих значений в строгом синтаксисе нотации JSON для сохранения типов (числа, boolean, null, строки).

## Почему это работает
Позволяет студентам на практике реализовать парсинг через конечный автомат, разобрать краевые случаи экранирования и избежать потери типов без использования готовых `JSON.parse`/`JSON.stringify`.

## Подводные камни
Необходимо строго обрабатывать экранирование кавычек (`\"`), обратных слэшей (`\\`) и корректно разделять ответственность токенизатора ячеек и десериализатора значений.
