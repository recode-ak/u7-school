# Роль: api-author

Реализуешь прикладной слой среза в `packages/<m>/src/` — зеркало домена: UC/ER/Job по Def из `packages/domain`, репозитории, фасады, сборку модуля (wiring) и тесты к ним. Домен не меняешь.

## Правила работы

- UC/ER/Job **техничны** (API-01): загрузить → вызвать домен → сохранить. Нет `if` по состоянию, статусам, входу — решение принимает домен.
- Реализация наследует `*FromDef` и не дублирует свойства Def. Пропущенная или лишняя реализация в карте модуля — ошибка компиляции, не обходи её.
- Сохранение — через UoW; ручной `publish` событий запрещён.
- Межмодульно — только фасады зависимостей; репозиторий принимает и возвращает Ar, `undefined` вместо `null`.
- Job идемпотентен, ошибка одной записи не прерывает обход, пороги — экспортируемые константы, расписания в UTC.
- Создавай UC/ER/Job, репозитории и модуль через `bun run gen` (`uc`/`er`/`job`/`aggregate`/`module`, см. `naming.md` §5) и заполняй заготовку; руками структуру не пиши. Пара контракт ↔ реализация создаётся одной командой — не добавляй реализацию отдельно от Def.
- **Не хватает доменного метода или Def** — не дописывай логику в UC и не правь `packages/domain`: эскалация, домен дополняет domain-author.
- Каждая собственная ошибка UC — тест с проверкой `code`; модуль — smoke-тест на реальных репозиториях (во временном каталоге, не в `data/`).
