# Repo, DCS, DQS — гайд

**Назначение:** хранение агрегата — порт `<A>Repo` (`<app>/<m>/<a>/<a>.repo.ts`) и его реализация (`<app>/<m>/infra/<a>.json-repo.ts`); доменные сервисы над несколькими агрегатами — DCS/DQS (`<domain>/<m>/<topic>.dcs.ts|.dqs.ts`), только когда без них нельзя.

---

## 1. Когда применять

- **Repo** — у каждого агрегата: загрузить Ar для операции и сохранить его. Только хранение (API-03): выборки по полям, без решений. Запись делает UoW (D-15), UC/ER/Job `save` не зовут.
- **Доменное правило**, а не DCS — проверка без мутации по нескольким агрегатам («не больше трёх открытых задач», [policy.md](./policy.md)).
- **DCS** — одна операция меняет несколько агрегатов или сочетает правила с операциями; возвращает `Result` (DOM-06). Две формы: решение по готовым агрегатам (образец ниже) и «вопрос → ответ» — DCS сначала отдаёт вопрос (готовый вход UC чужого модуля), прикладной слой задаёт его через `this.call`, затем DCS применяет ответ.
- **DQS** — вычисление на чтение поверх нескольких агрегатов, которое нужно нескольким потребителям (DOM-07). Список задач пользователя — не DQS: query UC читает агрегаты через репозиторий. В учебном модуле DQS нет.
- Не уверен — сначала метод Ar, затем правило; DCS/DQS — только по реальному потребителю ([domain-modeling.md](../domain-modeling.md) §1).

## 2. Команда

`dmg-core gen aggregate <m>.<a> --write` создаёт порт, `infra/<a>.json-repo.ts` и тест; в порт добавь `find*` под потребителей. `dmg-core gen dcs|dqs <m> <topic> --write` — заготовка сервиса с тестом.

## 3. Образец

- [task.repo.ts](../../src/testing/example/app/todo/task/task.repo.ts): `Repository<TaskAr>` и выборки `find*` — вход и выход `TaskAr`, `undefined` при отсутствии; `Result` в порте нет — `save` бросает `VersionConflict`, UoW превращает его в `VERSION_CONFLICT`.
- [task.json-repo.ts](../../src/testing/example/app/todo/infra/task.json-repo.ts): `aggregate = TaskArDef`, `Lock`, `assertVersion(aggregate, ar, stored)`, запись `ar.snapshot()`; разбор через `TaskArDef.state`.
- [task.json-repo.test.ts](../../src/testing/example/app/todo/infra/task.json-repo.test.ts): round trip, конфликт версии, параллельные записи, каждая выборка (`findActiveByParticipant` — без дублей).
- [task-release.dcs.ts](../../src/testing/example/todo/task-release.dcs.ts), [task-release.types.ts](../../src/testing/example/todo/task-release.types.ts) и [тест](../../src/testing/example/todo/task-release.dcs.test.ts): DCS над несколькими задачами — свои в архив, назначенные возвращаются владельцам; решает каждый Ar, выборке вызывающего сервис не верит; повтор ничего не меняет.

## 4. Чеклист правил

- API-03 — порт принимает и возвращает Ar; `save` сверяет версию, чтение-сверка-запись под замком.
- ARC-03 — в домене нет IO: порт и реализация — в прикладном слое, домен порт не знает.
- API-02 — в UC/ER/Job сохранение через UoW.
- DOM-06 — DCS только для мутации нескольких агрегатов; проверка без мутации — доменное правило.
- DOM-07 — DQS только читает и не знает транспорта.
- CODE-01 — порт `<a>/<a>.repo.ts`, реализация `infra/<a>.json-repo.ts` ([naming.md](../naming.md) §3).
- TST-04 — тесты репозитория изолированы: временный каталог.

## 5. Типичные ловушки

- **Решение в выборке.** «Текущая задача: последняя открытая, иначе последняя» — выбор, а не хранение: метод Ar или DCS.
- **Склейка выборок в ER.** Две выборки и слияние по uuid в ER — лишняя логика в прикладном слое: одна выборка порта под потребителя (`findActiveByParticipant`).
- **Мягкий разбор.** Пропуск битой записи с последующей перезаписью файла теряет её: разбор строгий, файл без неё не пишется.
- **`create` поверх старой записи.** Новый агрегат при занятом uuid — `VersionConflict`, а не перезапись (`assertVersion`).
- **Лишняя запись.** `save(ar.snapshot())` и `restore` в UC — признак порта на state; порт работает с Ar.
- **DQS «на вырост».** Сервис без второго потребителя — лишний слой; query UC читает репозиторий.

## 6. Как тестировать

Каждый `find*` — совпадение и отбор; `save` — round trip, устаревшая версия, новый агрегат при занятом uuid (файл не изменён), битая запись (исключение, файл не изменён). Временный каталог (`mkdtemp`), не рабочие данные. DCS — unit-тесты на готовых агрегатах: каждая ветка решения и повтор ([testing.md](../testing.md)).
