# Тестирование

**Назначение:** общие правила тестов. Правила с ID — раздел TST в [rules.md](./rules.md); как тестировать артефакт конкретного вида — §6 его гайда ([guides/](./guides/index.md)).

---

## 1. Принципы

- **TDD:** тест пишется до кода; покрытие > 80%.
- **Изоляция:** тесты не зависят друг от друга и от порядка; состояние — с нуля (`beforeEach` или свежие экземпляры).
- **Размер:** 10–20 строк; подготовку данных — в хелперы. Тест — документация поведения.
- **Группировка:** `describe` по методу/операции, `it` — по ветке поведения.
- **Один тест — одна причина падения.**

## 2. Проверка отказов

Проверяется **конкретная ошибка**, а не факт отказа:

```typescript
const res = task.complete(at);
expect(res.ok).toBe(false);
expect(res.ok ? undefined : res.error.code).toBe('TASK_ALREADY_DONE');
```

Хелперы из `dmg-core/testing`: `expectErr(res, 'TASK_ALREADY_DONE')` возвращает ошибку, суженную по коду; `expectOk(res)` — значение. Не зависят от раннера, при несовпадении бросают.

## 3. Пирамида

| Уровень | Что тестируется | Объём |
|---|---|---|
| **Схемы** | поля, границы, типы (детально) | все поля |
| **Ar** | каждая ветка `Ok`/`Err` мутирующих методов, переходы статусов, события; подключение схемы — 1–2 теста | максимальный |
| **Policy** | каждое правило: allowed и denied, роли, свой/чужой, контекст | все правила |
| **DCS / DQS** | сценарии координации и вычисления на готовых агрегатах | все методы |
| **Репозиторий** | контракт: restore/snapshot, поиск, `undefined` при отсутствии | контракт |
| **UC / ER / Job** | цепочки: нет актора → `UNAUTHORIZED`, нет сущности → `*_NOT_FOUND`, политика → `ACCESS_DENIED`, успех → регистрация в UoW и события; каждая собственная ошибка | по ошибкам |
| **Модуль** | smoke: один успешный вызов каждого UC на реальных репозиториях (временный каталог) | по UC |
| **Контрактные** | граф и правила MAN/ARC/ERR (`archCheck` из `dmg-core/arch`) | автоматически |

## 4. Моки

- Домен не мокается: он чистый, тесты работают с настоящими агрегатами.
- В прикладном слое мокаются порты (репозитории, фасады) — типизированно, без `any`.
- Время (D-34): домен получает момент аргументом операции (`task.complete(at)`) — в тесте Ar это просто константа. Прикладной слой берёт его из часов приложения (`this.now()` в UC/ER/Job); в тесте — `testAppContext({ at })` и `ctx.setNow(ts)` (`dmg-core/testing`). Глобальных часов нет, `Date` напрямую не читается.
- Готовые `testAppContext`, `recordingBus`, `memoryLogger`, `StubFacade`, `expectIdempotentReaction` — для UC/ER без реального приложения ([testing/index.ts](../src/testing/index.ts)); учебный модуль — [src/testing/example](../src/testing/example/example.arch.ts).

## 5. Защита от регресса и чистота правок

**Критично:** реализация, исправление или рефакторинг не приводят к регрессу функционала вне задачи.

- **Запрещено** менять функции и тесты вне области задачи.
- **Исключение:** если правка соседнего кода необходима (критическая ошибка или требование задачи) — сообщить владельцу задачи и получить явное разрешение. Агент-исполнитель в этой ситуации останавливается и возвращает эскалацию.
