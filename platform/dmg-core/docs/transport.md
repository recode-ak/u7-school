# Транспорт

**Назначение:** как манифесты превращаются во внешние контракты: HTTP, MCP, in-proc (бот, фасады). Генераторы транспорта — потребители графа (`dmg-core/graph`); в пакете пока не входят.

---

## 1. Общее

- Транспорт **генерируется** из Def: роутинг, валидация, описание контракта. Ручных ручек нет.
- Ответ — сериализованный `Result`:
  ```json
  { "ok": true, "value": { } }
  { "ok": false, "error": { "code": "TASK_ALREADY_DONE", "kind": "conflict", "payload": { } } }
  ```
- Сериализует и восстанавливает ответ Def UC: `serializeResult` / `restoreResult`; ошибка — без `label`/`description`, их клиент берёт из Def ([errors-result.md](./errors-result.md) §2). Код или payload вне контракта UC → `SERVER_INTERNAL`.
- **Выход UC переживает JSON без потерь:** только простые данные (время — `Timestamp`-число, без `Date`, `Map`, `undefined` в значениях). Клиент выход повторно схемой не проверяет: схема с преобразованиями второй раз не пройдёт.
- Агрегаты передаются **снапшотом**; клиент восстанавливает их в `ReadonlyAr` (домен изоморфный: чистый и синхронный пакет работает и на сервере, и в клиенте).
- Маппинг `kind` → представление транспорта — **только в адаптере**, ошибка о нём не знает.

## 2. HTTP

- Всегда `POST /api/<module>` с телом JSON-команды:
  ```json
  { "uc": "completeTask", "input": { }, "meta": { "requestId": "…", "version": 1 } }
  ```
- Команда — простые данные (D-49): `uc` — `name` Def UC, имени модуля в ней нет. Клиент собирает её из Def: `ucDef.command(input)` → `Command<D>`.
- `meta` — расширение без смены протокола: `requestId`, `version`.
- **`requestId` — одно намерение клиента:** клиент создаёт его один раз и повторяет при ретраях. Это и след (`Trace`, `correlationId`), и ключ идемпотентности: повтор command UC с тем же `requestId` от того же caller не исполняется дважды, клиент получает сохранённый ответ; тот же `requestId` с другим входом — конфликт. Отдельного ключа идемпотентности нет. `requestId`, созданный сервером (клиент его не прислал), в отсев не идёт; query не отсеиваются.
- Caller и `Trace` в команду не входят: их передаёт транспорт (заголовки, токен; D-46).
- `OPTIONS /api/<module>` — контракт модуля: UC с JSON Schema входа и выхода, ошибки, описание политики, `label`/`description`.
- **Модуль адресует транспорт** — URL, а не поле команды: `apiApp` выбирает `apiModule` по `<module>`, тот исполняет `dispatch(command, caller, trace)` и находит UC по имени. Неизвестный модуль или UC → `Err` `OPERATION_NOT_FOUND` (`not_found`, payload `{ module, uc }`). Адрес в URL нужен и для логов, прокси, выноса модуля в сервис.

Маппинг `kind` → HTTP-статус (в адаптере):

| kind | Статус |
|---|---|
| `validation` | 422 |
| `unauthorized` | 401 |
| `access` | 403 |
| `not_found` | 404 |
| `conflict` | 409 |
| `internal` | 500 |

## 3. MCP

- UC → **tool**: `name` (`<module>.<uc>`), `description` из Def, `inputSchema` из JSON Schema; аннотации: query → `readOnlyHint`, command → `destructiveHint` по необходимости.
- Граф → **resources**: карта модулей (L0), страницы модулей (L1) и агрегатов (L2), каталоги событий и ошибок — чтобы LLM понимала модель, а не только список ручек.
- `Err` → результат tool с `isError` и текстом из `label`/`denyMessage`.
- Caller: старт — только query, dev-окружение, явно заданный `user` (D-18). Мутации и авторизация по токену — позже.

## 4. In-proc

Форма та же, что у HTTP: команда `{ uc, input, meta? }` и `Result`. Отличие одно: JSON-сериализации нет, объекты передаются как есть (D-46).

- **Клиент — `moduleApi`:** знает адрес модуля (in-proc `apiModule` или URL) и объявляет API модуля. Вызов — `moduleApi.dispatch(ucDef.command(input))` → типизированный `Result<OutputOf<D>, UseCaseErrorOf<D>>`. Смена in-proc на HTTP меняет только адрес `moduleApi`, вызывающий код остаётся прежним.
- **UI (бот, web)** — через `moduleApi`; story обрабатывает `Err` по `code`, презентер решает, как показать.
- **Фасады** (`ModuleFacade`, D-43) — синхронный вызов в процессе через команду, типизированный сахар поверх; возвращают `Result`, `ReadonlyAr` строит вызывающий. При выносе модуля в сервис тот же контракт идёт по HTTP, агрегаты — снапшотом.
- **CLI** — тот же `moduleApi`.
