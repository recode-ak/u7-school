# Выжимка правил для инвентаризации тестов типов

**Назначение:** вход исполнителя инвентаризации вместо трёх гайдов. Источники: разбор-кандидат §2 (после трека — TST-10 пакета, `testing.md` §5.2), `dmg-core/docs/reference/testing.md` §5–5.1 (TST-08, TST-09). Здесь «рабочий код» — это `src/` пакета вне `*.test.ts`, включая учебный модуль `src/testing/example/`.

---

## Вердикты

- **удалить** — позитивный тест типа (`expectTypeOf(...).toEqualTypeOf`/`toExtend`, `Equal<…>`), если тот же вывод уже использует рабочий код: значение того же типа передаётся дальше, читается поле, вызывается метод. Ошибка вывода сломает `tsc` рабочего кода и без теста.
- **оставить** — негативный `@ts-expect-error` на публичную гарантию платформы. Обязательные четыре: (1) вызов Def вне `calls`, (2) ошибка вне Meta (`errors` Def), (3) мутация `ReadonlyAr`/`state`, (4) команда чужого модуля. Сюда же — другие запреты публичного API: тип случайно расширится до `string`/`any`, и сломается только этот тест.
- **оставить** — позитивный тест на неочевидный вариант, которым рабочий код не пользуется, но который гарантирует тип (например, сужение по коду ошибки, дискриминант union, опциональный вход).
- **сузить** — `@ts-expect-error` без пояснения после маркера, или под ним больше одной возможной ошибки (несколько аргументов/выражений неверны сразу). Нужно: пояснение после маркера и ровно одна ожидаемая ошибка в строке под ним. Вердикт «сузить» можно сочетать с «оставить».
- **оценить как обычный тест** — `@ts-expect-error` или `as never` нужны лишь чтобы дойти до рантайм-ветки (неизвестная команда, неверный вход в обход типов). Это не тест типа: судить по TST-08/TST-09 ниже — «оставить» или «удалить».

## Критерии обычного теста (TST-08, TST-09)

1. Правило проверяется на одном уровне: дубль того же сценария в другом файле/уровне — «удалить», указать, где покрыто (файл, `it`).
2. Вопрос к тесту: какая ошибка в коде пакета уронит его, и только его? Нет такой — «удалить».
3. Тавтология (константа против той же константы, ожидание, посчитанное тем же кодом) — «удалить».
4. Тест фейка, стаба или фикстуры, а не кода пакета — «удалить».
5. Рантайм-защита публичного API от входа в обход типов (JS-потребитель, `as never`) — код пакета, «оставить», если ветку больше ничто не проверяет.
