# Spec: `timestamp-data` — даты только числом

## Обзор

D-16 и D-34 пакета закрепили время как `Timestamp` — число миллисекунд UTC. Переходное `F.timestamp` в `dmg-core` до сих пор принимает ISO-строку, и такие строки лежат на проде, в контенте курсов и в фикстурах. Трек переводит все данные на числа и убирает чтение строки: после трека строковая дата в файле данных — ошибка чтения.

Отдельно — начало потока `stream.startDate`: сейчас это местное время Уральска (UTC+5), выданное за UTC («фальшивый UTC»): на проде — строка без зоны (`"2026-07-07T10:00"`), бот пишет `Date.parse("…Z")`, показ — через `getUTC*`. Трек переводит его в настоящий UTC: признак местного времени (нет зоны в строке) есть только сейчас, после перевода в число он теряется.

## Функциональные требования

- **ФР-1. Пакет.** В `dmg-core` `F.timestamp` принимает только конечное число ≥ 0, ISO-строку отвергает. Выпуск пакета v0.3.2 (с невыпущенными docs-коммитами D-87/D-88), правка D-16 в `decisions.md`, тесты `fields.test.ts`. u7-school переходит на `#v0.3.2`.
- **ФР-2. `JobRunJsonRepo`** (`platform/app/src/infra/job-run-json-repo.ts`) пишет и читает `last-runs.json` числом. Старые ISO-записи переводит скрипт миграции, не код репо.
- **ФР-3. Скрипт `scripts/migrate-timestamps.ts`.** Явный список «файл → пути полей дат», домен не импортирует (ARC-04, без нового C-DEBT). Идемпотентен; сухой прогон по умолчанию, запись — `--write`; каталог — `DB_DIR`. Итог по каждому файлу: переведено / уже число / не разобрано; неразобранная строка не чинится и не удаляется, при `invalid > 0` файл не пишется. Охват: users (`users.json`), streams (`streams.json`, `students.json`), peer-review (`campaigns.json`, `reviews.json`), `jobs/last-runs.json`, questionnaires, wish, courses (`courses`, `modules`, `lessons`, `steps`), а также любые другие файлы с полями `F.timestamp`, найденные при планировании. После выкатки скрипт удаляется.
- **ФР-4. Контрольное чтение.** После `--write` каждый файл разбирается строгими схемами state — классом в `platform/app` (корень сборки; скрипт импортирует только `@u7-scl/app`, ARC-04) — ошибок ноль.
- **ФР-5. Контент и фикстуры.** `data/courses/*.json` (под git) мигрируется скриптом и коммитится. `data/fixtures/**` — генерат (не в git): генератор миров `runners/u7-bot/tests/worlds` переводится на числа, фикстуры пересоздаются `bun run seed:fixtures`, кэш мира сбрасывается. `generatedAt` манифеста `world.json` — не state, за рамками. Литералы ISO-дат в тестах и конструкторах фикстур — числами; тесты «legacy ISO читается» переписываются на «ISO отвергается».
- **ФР-6. Выкатка на прод — в треке, выполняет агент:**
  1. проверка, что `data/courses` на проде не изменён относительно тега;
  2. остановка бота;
  3. `bun run backup before-timestamp-data`;
  4. чекаут релиза и `bun install` (бот не стартует);
  5. сухой прогон, итог — Нурболату;
  6. **подтверждение Нурболата**;
  7. `--write` и контрольное чтение;
  8. старт бота, проверка лога и oplog.

  Откат: восстановление из снимка (`docs/backup.md`) и чекаут предыдущего тега.
- **ФР-7. `stream.startDate` — настоящий UTC.**
  - Миграция: `startDate`-строка без зоны разбирается как `+05:00` (−5 ч); строка с явной зоной или `Z` — как есть. Число в `startDate` до миграции — «фальшивый UTC» от бота, сдвиг по форме не определить: миграция считает его `invalid` и останавливается (на проде 2026-11-15 чисел нет, все 9 потоков — строки без зоны). Сухой прогон печатает счёт «без зоны / с зоной / число».
  - Ввод: `create-stream` разбирает введённые дату и время как `+05:00`.
  - Вывод: дата и время старта (`view-stream`, `wish-invite` и др.) — в зоне UTC+5 через одну константу зоны проекта (позже её заменит цепочка C-DEBT-43).
  - Тесты «10:00 по Уральску ↔ 05:00Z» в обе стороны.
  - Остальные даты (`createdAt`, `updatedAt`, `issuedAt`…) ставятся из `clock()` и уже в UTC — без сдвига.

## Нефункциональные требования

- Записи меняются только в полях дат: порядок записей, прочие поля, `version`, значения `updatedAt` сохраняются. Перевод `Date.parse` без потери точности.
- TDD: тесты скрипта на фикстурах — смешанный формат, идемпотентность, `invalid` останавливает запись, `startDate` без зоны и с зоной.
- Без новых зависимостей.

## Критерии приёмки

1. `F.timestamp` из `dmg-core` v0.3.2 отвергает строку, тест в пакете есть; u7-school на v0.3.2.
2. Поиск ISO-дат в `data/courses`, пересозданных `data/fixtures` (кроме логов) и тестовых мирах пуст; в `.ts` — только нарочные негативные тесты.
3. На проде после миграции строковых дат в файлах данных ноль, контрольное чтение без ошибок, бот работает на новом релизе.
4. `last-runs.json` пишется числом.
5. `startDate` всех потоков на проде — настоящий UTC (местное 10:00 → 05:00Z); создание и показ потока работают в UTC+5, тесты в обе стороны есть.
6. `bun run check` и полный `CI=true bun test` зелёные, `arch:check` без нарушений.
7. Пункт `timestamp-data` убран из `roadmap.md`, D-16 обновлён, итог — `summary.md`.

## За рамками

- Персональные часовые зоны (C-DEBT-43): зона пользователя и школы.
- Отображение прочих дат (кроме старта потока).
- Логгеры и имена файлов бэкапов — ISO там текст, не данные.
- `data/oplog` и `data/replay` — служебные журналы с TTL.
