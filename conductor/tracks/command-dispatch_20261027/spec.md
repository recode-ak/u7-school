# Спецификация: command-dispatch

## Обзор

Исполнение UC в прикладном слое строится на простой сериализуемой команде, а не на ссылке на Def. Def остаётся источником типов и сахаром для клиента: из него собирается команда. UI (бот, web), CLI, межмодульные фасады и будущий HTTP идут одним путём, и вынос модуля в сервис сводится к замене транспорта.

Старт — после [dmg-core-oop](../dmg-core-oop_20261027/) (Def — классы).

**Мотивация.** Слой `ui-bot-story` сейчас передаёт UC-Def, и для in-proc это нормально. Но `ui-web-story` должен передать по транспорту JSON, а бэк — найти по нему адресный UC. Городить на HTTP-сервере восстановление Def из JSON не нужно: цепочка `apiApp` → `apiModule` строится на DTO команд, а генерация команды — на основе Def.

## Функциональные требования

1. **`Command`** — простые данные: `{ uc, input, meta? }` (`meta`: `requestId`, `version`, идемпотентность — см. `transport.md`). **Имени модуля в команде нет:** модуль адресует транспорт (URL на бэке, `moduleApi` на клиенте). Если появится причина класть модуль в данные, это делает `moduleApi`, а не команда. Caller и Trace в команду не входят, их передаёт транспорт.
2. **Сборка по Def:** `ucDef.command(input)` → `Command<D>` с фантомным типом `D`. Def собирает только команду и ничего не знает про адрес.
3. **Исполнение на бэке:** `apiApp` выбирает `apiModule` по адресу транспорта → `apiModule.dispatch(command, caller, trace)` → UC по имени (`ModuleFromDef` ищет по `name`, а не в `Map` по ссылке на Def) → обычный конвейер UC (`checkCaller` → `parseInput` → …). Неизвестный модуль или UC → `Err` (код уточняется в плане).
4. **Клиент:** `moduleApi` знает адрес модуля (URL или in-proc `apiModule`) и объявляет API (доменное или абстрактное); `moduleApi.dispatch(ucDef.command(input))` возвращает типизированный `Result<OutputOf<D>, UseCaseErrorOf<D>>`.
5. **Сериализуемый ответ:** `Result` в формате `transport.md` (`{ ok, value }` / `{ ok, error: { code, kind, payload } }`) с обратным восстановлением. In-proc можно не гонять через JSON, но форма та же.
6. **Межмодульные фасады** (`ModuleFacade`, D-43) идут через команды; типизированный сахар поверх сохраняется.
7. **Перевод потребителей:** бот-истории (`runners/u7-bot`), CLI и тесты — на `moduleApi` + `ucDef.command(...)`.
8. **Решение:** новый D-xx в `decisions.md` («Def — типы клиента, команда — исполнение; модуль адресует транспорт»), обновить `transport.md` §2 и §4.

## Критерии приёмки

- В прикладном слое и раннерах нет вызовов `handle(def, …)` по ссылке на Def.
- Тест на круговой путь JSON: команда → `JSON.stringify/parse` → `dispatch` → сериализованный `Result` → восстановление.
- Тесты типов: `Command<D>` и `moduleApi.dispatch` выводят `InputOf`/`OutputOf`/ошибки.
- `bun test`, `tsc --noEmit`, `biome check`, `arch:check` зелёные во всём репо.

## За рамками

- HTTP-сервер и MCP-адаптер (отдельные треки транспорта).
- Авторизация по токену.
