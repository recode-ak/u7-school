# Инвентаризация тестов: прикладной слой `questionnaire`

Трек `tst-cleanup_20261105`, фаза 2. Область — `modules/questionnaire/src/**/*.test.ts` (12 файлов). База: `cd modules/questionnaire && bun test` → **113 pass, 0 fail** (проверено в worktree `tst-cleanup`).

Основание: закономерности [`test-bloat.md` §2](../../../roadmap/test-bloat.md) (Б-1…Б-13), правила `node_modules/dmg-core/docs/reference/testing.md` §3, §5, §5.1 (TST-08, TST-09), [`bot-test.md` §2 п. 5](../../../../architecture/ui/bot-test.md), решения трека [`spec.md`](../spec.md) «Решения». Вопрос к каждому тесту: **какая реальная ошибка в коде модуля уронит его и только его?**

Особенность модуля: **весь домен анкет (`Ar`, `Policy`, `Engine`, схемы, ступени `sweepIdle`) уже покрыт тестами в `domain/src/questionnaire/**`**, а модуль — тонкий: 9 UC по 10–25 строк каждый (+ Job 20 строк). Поэтому доля дублей здесь выше, чем в `stream`: уникальны в модуле только загрузка (`load` + свой `*_NOT_FOUND`), регистрация в UoW, параметры вызовов репозитория и `subject(caller)`.

Номера строк — по текущему коду worktree. Каждая ссылка «где покрыто» проверена: файл существует, на указанной строке начинается `it(`/`test(`/`it.each(`, тест проверяет то же и сам не кандидат (цепочек «A покрыт B, B удалён» нет).

Действия: `удалить` / `слить в <файл>:<строка>` / `переписать` / `перенести` / `отложить`.
