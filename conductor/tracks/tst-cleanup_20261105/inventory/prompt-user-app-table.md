## Решения, которые обязательны (общие)

- **Схемы (Б-8):** удаляются тесты приёма/отказа полей платформы. Остаются: своя логика схемы (`refine`/`transform`), отказ прежних форм записи, схема state, разбираемая при чтении файла, — одной таблицей «валидно/невалидно» на схему.
- **Паспорта Def (Б-7):** удаляются все. На модуль остаётся **один** тест состава — доменный `domain/src/user/user.module.test.ts:7` (UC, `dependsOn`; если ему чего-то не хватает — «переписать»).
- **Тексты `label`/`denyMessage` ошибок** не тестируются (TST-09). Одиночные `expect` на них внутри полезных тестов — раздел «Остающиеся проверки `label`» (файл:строка `expect`); снимаются в этом же срезе.
- **Одно правило на двух уровнях (Б-1):** правило проверяет владелец (Ar / DCS / DQS / Policy домена). У UC модуля остаются: один сквозной сценарий на UC и то, что делает только UC (загрузка, свой `*_NOT_FOUND`, запись в UoW, публикация); Policy-отказ UC — **один** кейс на модуль, не удаление всех.
- **Policy домена:** каждое правило — allowed и denied (`testing.md` §3); «без субъекта — denied» — как в `questionnaire-domain-delete.md`.
- **Бот:** integration — связка слоёв, e2e — пользовательская история. Тесты, красные сейчас из-за `course-dmg` (TR-57 в `conductor/architecture/debt.md`), **не удалять** — «отложить до course-dmg».
- Каждое удаление — только если указано, где покрыто то, что тест мог бы поймать. «Нигде» допустимо только для Б-9/Б-11/Б-12/Б-13 — с одной фразой.
- **Б-13 (мёртвый экспорт):** тест не трогаем — `отложить: удалить с кодом`.
- **Направление Б-1:** удаляется копия **выше** владельца. Доменный тест правила (Ar/DCS/DQS/Policy/rules) нельзя удалять со ссылкой «покрыто UC модуля» — наоборот, удаляется копия в UC. Исключение — доменные тесты Def UC (`domain/src/user/**/uc/*.test.ts`): это паспорта/схемы (Б-7/Б-8), поведение держит модуль.
- Ссылка «где покрыто» в другой уровень ведёт только на тест, который инвентаризация того уровня (`user-dossier-domain.md` §4) считает полезным. Проверяй каждый путь.
- Новые Н-ID инвентаризации в таблице записывай как `Н<n>-app` (у каждого уровня своя нумерация).


## Решения по открытым вопросам `user-app.md`

1. **Ссылки на домен** — доменные тесты `a-root`/`policy` остаются (кроме мёртвых `canRead`/`canEdit`/`isSubscriber`/`isGuest`/`isStudent` — их orchestrator удаляет с кодом; на тесты этих методов не ссылайся). Перед ссылкой проверь, что доменный тест есть в `user-dossier-domain.md` §4 и не помечен как кандидат в §3.
2. **Механизм `userFacade.notify`** (`notify-user` UC → `user.notified` → сторя `notify`) — задуманная инфраструктура (трек `user-notify`, `conductor/roadmap.md`), **код остаётся**. Его тесты оцениваются по существу, как обычные.
3. **Мёртвая ветка `telegramId === undefined`** (`notify.story.ts:60`) — orchestrator удалит с кодом: `notify.story.test.ts:135` — `отложить: удалить с кодом`. То же для `total`/`appliedFilters` ответа `list-users`, если у них нет потребителей вне тестов (проверь grep): их тесты — `отложить: удалить с кодом`.
4. **Схемы legacy-команд `user`** — правило общее: приём/отказ полей платформы (`uuid`, `picklist`, обязательность) — `удалить` (Б-8, «нигде»: платформа). Своя логика схемы (`refine`/`transform`/связь полей) — одна таблица «валидно/невалидно» на схему остаётся.
5. **`register-guest-uc.test.ts:144`** (`rejects` без `await`) — `переписать`: добавить `await`.
6. **Состав модуля** — тест состава один — доменный `user.module.test.ts:7`. `modules/user/src/user.module.test.ts`, `api/module.test.ts` — `удалить` (Б-7), если в них нет сборки/инфраструктуры, которую домен не видит (репозиторий, фасад, подписка) — тогда оставить **один** тест сборки (`переписать`).
7. **Бот:** два красных `user-notify.e2e.test.ts` (`:186`, `:254`) и прочие тесты про завершение курса/модуля — `отложить до course-dmg`.
