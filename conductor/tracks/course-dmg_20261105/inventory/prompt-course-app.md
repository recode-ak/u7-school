# Инвентаризация тестов `course-app` (трек course-dmg_20261105, Ф8)

Ты работаешь в репозитории u7-school (`main`). Задача — **только чтение кода и запись одного файла отчёта**. Все тексты — на русском. Ничего не удаляем.

## Как работать экономно

- Читай связанные файлы **одним вызовом** (несколько путей в `cat`/`read` сразу), не перечитывай уже прочитанное.
- Список тестов с номерами строк уже готов: `conductor/tracks/course-dmg_20261105/inventory/course-app-tests.txt` (`файл:строка | начало строки`; `it.each`/`test.each` разворачиваются в несколько тестов, многострочные объявления могут не попасть в список — сверяйся с файлом). Не перебирай тесты циклами в bash.
- Проверки — только `cd modules/course && bun test` (база 330).

## Цель

Найти тесты, удаление которых не уменьшит защиту от реальной ошибки в проде. Вопрос к каждому `it`/`test`: **«какая реальная ошибка в коде модуля уронит этот тест и только его?»** Нет такой — кандидат.

Закономерности уже собраны: `conductor/roadmap/test-bloat.md` §2 (Б-1…Б-17) и §6 (рекомендации для `course`) — прочитай эти два раздела. Размечай кандидатов **сразу Б-ID**. Новая закономерность — номер Н1, Н2… с полным описанием (признак, почему бесполезен, примеры, как появляется).

Выжимка правил (`dmg-core` testing.md §3, §5, §5.1; TST-08, TST-09):
1. Правило проверяет владелец: Ar / DCS / DQS / Policy домена. UC модуля — один сквозной сценарий на UC плюс то, что делает только UC (загрузка из репозитория, Policy-отказ, своя ошибка, запись в UoW, публикация).
2. Паспорта Def (состав `errors`/`emits`/`calls`, `normalize(`, `ArchChecker`) — дубль `arch:check` (Б-7). На модуль остаётся **один** тест состава: список UC (ER, Job) и `dependsOn`.
3. Схемы (Б-8): приём/отказ полей платформы (`F.uuid`, `picklist`, `variant`) не тестируем. Остаются: своя логика схемы (`refine`/`transform`, инварианты), отказ прежних форм записи, схема state, разбираемая при чтении файла, — одной таблицей «валидно/невалидно» на схему.
4. Тексты `label` ошибок не тестируются (TST-09).
5. Поведение платформы (`UNAUTHORIZED`, `VersionConflict`, умолчания story, «событий нет» отдельным `it`) — Б-9.
6. Бот: story-тест — поведение экрана, integration — связка слоёв, e2e — пользовательская история; повтор между ними — Б-4.

**Не трогать (§6):** строгое чтение `courses.json` (инвариант программы при чтении — защита данных); тесты этапов-меток (курс без этапов / один / несколько) — по одному на класс входа на уровне владельца; legacy ISO / даты без секунд в репозиториях.

## Область

- `modules/course/src/**/*.test.ts` (22 файла, не `node_modules`). Особое внимание: UC-тесты против доменных DQS/Ar/Policy (Б-1), `course.module.test.ts` против `course.module.serves.test.ts` и `domain/src/course/course.module.test.ts` (один тест состава на модуль), репозитории `infra/*.json-repo.test.ts` (строгий разбор и legacy-формы — не трогать; повтор схемы state — Б-8).

Доменные тесты `domain/src/course/**` читай только для поиска повторов (владелец правила — домен); их не оценивай.

Чтобы понять, что тест защищает, читай проверяемый исходник. `node_modules/dmg-core/src` — только чтобы понять, не проверяет ли тест гарантию платформы.

## Результат

Создай файл `conductor/tracks/course-dmg_20261105/inventory/course-app.md` (только его):

1. **Сводка** — число тестов по файлам: всего / полезен / сомнителен / пуст.
2. **Закономерности** — по Б-ID: число случаев, 2–4 примера `путь:строка`; новые Н-номера — с полным описанием.
3. **Кандидаты** — таблица только по «сомнителен»/«пуст»: `путь:строка` | имя теста | Б-ID | где покрыто (`путь:строка` начала конкретного `it`, или «нигде» с фразой) | что делать (удалить / слить / переписать / перенести).
4. **Полезные тесты** — одной строкой на файл: «файл — N тестов, полезны, защищают …».
5. **Открытые вопросы** — то, что решает orchestrator (до 7 пунктов).

Будь строгим, но честным: сомневаешься — «полезен». Каждая ссылка «где покрыто» указывает на конкретный `it`, который сам не кандидат.

## Не трогай

Любой код и тесты, `conductor/` (кроме своего файла), `data/`, `node_modules/`. Не запускай seed, не коммить. Другие отчёты `course-*.md` пишутся параллельно — не читай и не пиши их.

## Отчёт

Путь к файлу, число тестов, число кандидатов, 3–5 главных закономерностей одной строкой.
