# F-111. Лог операций для расследований: патч полей state и инструмент чтения

## Обзор

Запись лога операций (D-43, D-73) сейчас показывает, *что* записано (агрегат, uuid, версии), но не *как*; средства чтения лога в пакете нет — только `grep` по JSONL. Задача — дать из коробки удобные инструменты исследования работы и действий: в `dmg-core` — патч изменённых полей с маскированием персональных данных во всей записи (вход, выход, ошибка, патч), срок хранения лога и CLI-читатель; в u7-school — подключение и разметка персональных полей. Решение пакета — D-85 (снимает оговорку D-73 «патч не входит»). Источник — кандидат F-111 (карточка C-12 ревизии, заготовка `roadmap/oplog-state-patch.md`).

## Функциональные требования

**ФТ-1. Патч в `writes`.** `AggregateWrite` получает необязательное `changes: { path, from, to }[]` — разница базового состояния и состояния при записи.
- Базовое состояние — ссылка внутри `Aggregate` (`baseline`): ставится при восстановлении и в `markStored()`; `mutate` заменяет `current` новым объектом, поэтому копировать не нужно, у query цена нулевая. `Committable` получает геттер `baseline`. Патч считает `UnitOfWork.commit` после `save`. (UC регистрирует Ar в UoW уже после мутации — снять «до» в `register` нельзя.)
- Объекты разбираются по полям (путь через точку: `profile.telegram`); массивы и примитивы — одно значение (лист).
- Созданный агрегат (`from: null`) — поля верхнего уровня с `from: undefined`.
- Служебные поля (`BaseEntityFields`: `uuid`, `version`, `createdAt`, `updatedAt`) в патч не входят — они уже в записи.

**ФТ-2. Персональные данные — пометка на схеме, маскирование всей записи.**
- **Пометка** — `F.sensitive(schema)` (`v.metadata({ sensitive: true })` valibot) на поле схемы. Ставится один раз — в state или VO — и переходит во все производные схемы: выход UC из `view()` и state (D-39), вход из тех же VO, payload событий и ошибок. Путей строками нет — проверять «неизвестный путь» не нужно.
- **Маскировщик** — класс (`SensitiveMask`) обходит значение по схеме: `object` (entries), `array` (item), `optional`/`nullable`/`nullish`, `pipe`, `record` (value), `variant`/`union` (поле маскируется, если помечено хотя бы в одной ветке), обёртку `withEntityDefaults`. Значение помеченного поля — `'[redacted]'`; поля вне схемы (лишние ключи сырого входа) — как есть.
- **Где применяется** — вся запись лога операций, в базе операции (`OperationRun`) перед `append`:
  - `input`: UC — по схеме входа; ER — по схеме payload события (`EventDef`); Job — `null`;
  - `output` команды, ER, Job — по схеме выхода;
  - `payload` ошибки — по схеме payload `ErrorDef`;
  - `changes` — изменение помеченного поля state — `{ path, redacted: true }`, без значений и хеша (короткие значения подбираются по хешу); маскирование в UoW — значения state не покидают его.
- Сбой маскирования — значение целиком `'[redacted]'` и `warn`: при сомнении — не писать.
**ФТ-3. Порог размера.** Значение `from`/`to` больше порога (по умолчанию 1 КБ JSON) — дайджест `ValueDigest` `{ size, hash }` (имя `TruncatedValue` уже занято усечением `input`/`output`) (sha256, первые 12 символов): виден факт изменения, значения сравнимы между записями. Порог — в `JsonlOperationLog` рядом с `SizeLimit` (опция). Пример: замена `contentSnapshot` потока (F-80) — одна строка «заменено, N байт, hash».

**ФТ-4. Срок хранения.** `JsonlOperationLog` — опция `retainDays`: файлы дней старше срока удаляются при смене дня. По умолчанию — без удаления (поведение пакета прежнее).

**ФТ-5. CLI чтения — `dmg-core oplog <dir>`.** Только чтение. Фильтры:
- `--request <id>` — цепочка по `correlationId`: операция, порождённые реакции, Job и вложенные вызовы;
- `--aggregate <uuid>` — история изменений агрегата (патчи по версиям);
- `--subject <id>` — действия субъекта;
- `--module`, `--op`, `--failed`, `--since` / `--until` (дата или ISO-время).

Вывод — читаемая лента (время, `модуль.операция`, кто, итог, изменения); `--json` — исходные записи. Старые записи без `changes` читаются. Логика — класс-читатель (`OperationLogReader`), пригодный и без CLI.

**ФТ-6. u7-school.**
- Пометить `F.sensitive` в state и VO: user (`name`, `telegramId`, `nick`), questionnaire (`answers`, `draftAnswers`, `ownerInfo`), review (`text`), stream (`enrollmentKey`, `telegramGroupInvite`), student (`abandonDetails`, `completionDetails`, `notices` — после аудита VO). У wish, review-campaign и контента курса ПД нет; агрегата «бот» нет.
- Аудит схем входа и выхода UC, payload событий и ошибок с ПД, собранных не из помеченных state/VO (например, вход регистрации пользователя), — пометить там же.
- `retainDays: 90` — в `platform/app/src/u7-app.ts` (единственное место создания лога).
- Скрипт `bun run oplog …` — CLI по `DB_DIR/oplog`.
- `docs/backup.md`, раздел данных `AGENTS.md`.

## Нефункциональные требования

- Без новых зависимостей (sha256 — `crypto`).
- Сбой расчёта патча или маскирования не ломает операцию (как сбой записи лога сейчас).
- Рост объёма лога умеренный: у query патча нет, крупные значения — `{ size, hash }`.

## Критерии приёмки

1. Command, изменившая поле, — в логе `changes` с `from`/`to`; у query `changes` нет.
2. Изменение помеченного поля — `redacted: true` в `changes`; помеченные поля во `input`, `output`, `payload` ошибки и payload события (вход ER) — `'[redacted]'`; значения нет нигде в строке JSONL (тест ищет значение).
3. Пометка переходит в производные схемы: выход из `view()`/state, вход из VO; маскировщик проходит optional/nullable/pipe/array/record/variant/union и обёртку `withEntityDefaults`.
4. Значение больше порога — `{ size, hash }`; одинаковые значения — одинаковый hash.
5. `retainDays: N` — файлы старше N дней удалены, остальные не тронуты.
6. CLI: `--request` выводит цепочку UC → ER → вложенные; `--aggregate` — историю патчей; фильтры комбинируются; старые записи без `changes` читаются.
7. u7-school: персональные поля state, VO и схем операций помечены (тест по списку аудита); на фикстурах в логе нет имён и Telegram ID; `bun run oplog --request <id>` на фикстурах даёт ленту.
8. D-85 в `decisions.md`; новый `docs/reference/oplog.md`, правки guides, `llms.txt`, `docs/index.md` сходятся с кодом; выпущен тег `dmg-core`, u7-school на нём.

## За рамками

- Web-интерфейс, поиск по нескольким серверам.
- Бэкап `oplog` (D-43 не меняется).
- Хранение в БД, индексы (хватает линейного чтения JSONL).
- Откат агрегата по патчу.
