# Задание пилотного среза (Фаза 3)

Общее для обеих сред (Claude Code, pi). В worktree кладётся как `pilot/task.md`.

---

Ты — сессия-оркестратор в репо пакета `dmg-core` (временный worktree). Работаешь **автономно**: человека рядом нет, вопросов не задавай. Где нужен выбор — выбирай рекомендованный вариант и записывай допущение в `pilot/assumptions.md` (что выбрал, почему, кто предложил).

## Цель

Пройти конвейер ролей `dmg-*` на одном срезе учебного модуля `todo` и сохранить отчёт каждой роли. Код среза — побочный продукт: его оценят, но не закоммитят.

## Срез: «Отложить задачу до даты»

Учебный модуль: домен — `src/testing/example/todo/`, прикладной слой — `src/testing/example/app/todo/`. Пакет подключён к себе как `node_modules/dmg-core` (симлинк на корень) — пути ролей вида `node_modules/dmg-core/…` рабочие.

Поведение:
1. Владелец задачи может отложить **открытую** задачу до момента в будущем. Повторный вызов переносит дату.
2. Нельзя отложить задачу не в статусе `open` и нельзя — на момент в прошлом или текущий.
3. Выполнение задачи снимает отсрочку.
4. Выход query задачи отдаёт дату отсрочки, если она есть.
5. Уже сохранённые задачи (без отсрочки) читаются как прежде.

## Конвейер

Порядок — `docs/process.md` §4 и `agents/README.md`. Каждый шаг — вызов субагента (Claude Code — `Agent` с `subagent_type`; pi — инструмент `subagent`); роли из `.claude/agents/` или `.pi/agents/`.

1. `dmg-tech-lead` — черновик брифа среза. Бриф записываешь ты в `pilot/brief.md`.
2. `dmg-test-designer` — red-тесты по брифу; убедись сам, что тесты красные.
3. `dmg-domain-author` — домен (state, Ar, Policy, правила, события, ошибки, Def).
4. `dmg-api-author` — прикладной слой (UC, репозиторий, сборка модуля).
5. Гейт после каждого автора — ты сам: `bun run check`. Красный — верни вывод тому же автору; второй красный подряд по той же причине — остановись, опиши в `pilot/result.md`.
6. `dmg-data-keeper` — diff меняет `state` и репозиторий.
7. `dmg-reviewer` — по diff среза. Замечания `error` — автору на правку → `check` → повторное ревью (не больше одного круга).

Субагенту передавай путь к брифу и конкретный шаг; бриф в вызов не копируй.

## Границы

- Код — только в `src/testing/example/**`. Остальные файлы пакета (роли, `docs/`, `src/` вне example) не трогать.
- Никаких git-операций, меняющих историю или дерево: `commit`, `checkout`, `reset`, `stash`, `clean`. Читать — можно.
- Зависимости не добавлять.

## Что оставить в `pilot/`

- `brief.md` — бриф (с отчётами авторов и ревьюера в конце).
- `reports/<n>-<роль>.md` — отчёт каждого вызова дословно, `n` — порядковый номер вызова.
- `assumptions.md` — допущения.
- `result.md` — итог: таблица «шаг → роль → статус (ок / повтор / сбой) → число вызовов»; итоговый `bun run check` (pass/fail); где роль ошиблась, вышла за границы, спросила вместо решения или дала шум; что поправить в промптах ролей.
