# Spec: dmg-cleanup_20261028

## Обзор

Уборка в `dmg-core` и подготовка к дальнейшей работе над u7-school: оформить параллельную разработку платформы, перевести тесты прикладного уровня пакета на фейки, отсев повторов команд по `requestId`, `update_id` Telegram до UC, свой показ ошибок DMG в боте. Наследник заготовки [bot-request-id](../../roadmap/bot-request-id.md) (вариант B).

## Функциональные требования

**ФР-1. Параллельная разработка платформы.** `AGENTS.md`, `conductor/architecture/agents.md`: `dmg-core` (в будущем `dmg-ui`) развиваются параллельно с u7-school; агенты вправе править репо пакета по `architecture/index.md` §«Правка платформы»; коммит в репо пакета отдельно, SHA — в коммите u7-school.

**ФР-2. Тесты UC/ER/Job на фейках.**
- `MemoryRepo<A>` в `dmg-core/testing`: наследник `VersionedRepository`, снапшоты в памяти, `seed(...)`, просмотр записанного («ничего не записано»), `failOn(uuid)` — сбой записи.
- `find*` фейк не реализует: тест задаёт готовый ответ (как `StubFacade.answer`); корректность выборки — контрактный тест репозитория.
- Тесты UC/ER/Job примера переведены на фейк; сценарии сохранены 1:1.
- Smoke модуля и контракт репозитория — на настоящем репо во временном каталоге (без изменений).
- Пирамида: UC/ER/Job — фейк; репозиторий и модуль — временный каталог; UI e2e — настоящие репозитории. Правка `testing.md` §4, гайдов `use-case`, `event-reaction`, `job`, `module`, `repo`.
- Шаблон теста UC в `gen` (`operation.ts`) — на фейке.
- Существующие тесты UC u7-school не переписываются: запись в debt «переводятся по мере касания».

**ФР-3. Отсев повторов command UC (DEBT-1 dmg-core).**
- Решение D-NN в `decisions.md` пакета.
- `Trace` различает `requestId` клиента и созданный сервером; серверный и query в отсев не идут.
- Порт `ReplayStore` (TTL) в `dmg-core/app` + реализация в памяти.
- `dispatch`: повтор (`caller` + `requestId`, тот же вход) — сохранённый ответ без исполнения; другой вход — `REQUEST_CONFLICT` (`conflict`).
- `transport.md` §2 обновлён, DEBT-1 снят.

**ФР-4. `requestId` из `update_id` (вариант B, DEBT-38).**
- Транспорт кладёт `update_id` в контекст запроса, который story уже получает.
- `dispatchUc`: `requestId = tg:<update_id>#<n>` (n — номер вызова UC за апдейт; story детерминирована, при повторе n тот же), `correlationId = tg:<update_id>` — общий для вызовов апдейта. `warn` не пишется.
- Файловый `ReplayStore` в u7-school: `data/replay/` с TTL — переживает рестарт (основной случай повторной доставки Telegram). Каталог не защищён git, в бэкап не входит (как `oplog`); внесён в `AGENTS.md`, `docs/backup.md`.
- DEBT-38 снят. Новый долг: в `dmg-ui` контракт story несёт id запроса явно; неявный контекст — временный.

**ФР-5. Показ ошибок DMG в боте (DEBT-37).** `ucErrorNotify` показывает `DomainError` по `kind` и тексту из Def, без `toLegacyError`/`AppException`. DEBT-37 снят.

## Нефункциональные требования

- TDD по шагам (red → green); `bun run check` зелёный в пакете и проекте после каждой задачи.
- Данные `data/` не трогаем (кроме нового каталога `data/replay/`); без пушей и деплоя.
- Изменение контракта пакета — через решение в `decisions.md` пакета.

## Критерии приёмки

- ФР-1–ФР-5 выполнены; маркеров DEBT-1 (пакет), DEBT-37, DEBT-38 нет.

- Заготовка `roadmap/bot-request-id.md` удалена, кандидат `[?]` снят.
