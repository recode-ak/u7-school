# Spec: уборка перед dmg-ui

## Обзор

После релиза v0.3.0 проект приводится в чистое состояние перед большой фазой `dmg-ui`: единая система долга с проверкой из `dmg-core`, разбор `TODO.md`, тестовые хелперы платформы, выравнивание ранних модулей (`wish`, `peer-review`) по образцу поздних, ревизия roadmap и документации по правилу «знание сохраняется, история удаляется». Итог — документ-вход для spec `dmg-ui`.

Трек `timestamp-data` (релиз v0.3.2) — отдельный, после выкатки v0.3.0. Режим работы: тактику и мелкие доменные вопросы orchestrator решает сам; стратегические и доменные — Нурболату (журнал `TR` больше не ведётся, знание — в `decisions.md` и гайды).

## Функциональные требования

**ФР-1. Система долга.** Папка `conductor/debt/`:
- `README.md` — правила (формат записей, закрытие, триггер, разбор долга в конце трека и перед релизом);
- `code.md` — `C-DEBT-n` (из `conductor/architecture/debt.md`);
- `tests.md` — `T-DEBT-n` (из `conductor/roadmap/test-bloat.md`: закономерности — в правила, журнал — записями);
- `product.md` — `D-DEBT-n` (технические пробелы продукта; концептуальное — в `roadmap.md`).

В реестрах — только открытый долг: закрытая запись удаляется, единственный след — коммит `закрыть <ID>`. Реестр хранит строку «последний выданный ID». У каждой записи — трек-владелец или поле **Триггер**. Журнал TR (§6 `debt.md`) удаляется; живое знание из него — в `decisions.md` и гайды; новые TR не заводятся.

**ФР-2. Единая проверка долга в `dmg-core`.** `dmg-core/arch` экспортирует проверку в формате allowlist (Место / Признак / Корень, ID только в `biome-ignore`, маркеры временности) и сверку всех трёх реестров: `DEBT` — по коду, `T-DEBT` — существование файлов, `D-DEBT` — формат. Это объединение двух реализаций (`dmg-core/scripts/debt-check.ts` и `checkDebt`/`checkTempMarkers` из `scripts/domain-check.ts`) с переносом их тестов в пакет. Пакет переводит свой `debt.md` на неё; u7-school вызывает её из `scripts/arch-check.ts`. Релиз `dmg-core` (тег, смена `#vX.Y.Z` в проекте).

**ФР-3. Разбор `TODO.md`.** Каждый пункт: закрыть (сделано или неактуально) / перенести в `DEBT`, `T-DEBT`, `D-DEBT`, `roadmap.md` / во вход `dmg-ui`. Принятые решения:
- зачисление в активный поток и восстановление «забросившего» студента — `D-DEBT`, после `dmg-ui`;
- wizard (форма ввода по схеме входа UC) и каскад `init(resolve)` в UI — вход `dmg-ui`;
- `init/start/stop` на бэкенде — закрыт (DMG собирает зависимости конструктором).

Файл удаляется.

**ФР-3а. Ссылки.** Пути на `architecture/debt.md`, `roadmap/test-bloat.md`, `migration.md`, `TODO.md` и ID `TR-n` вне архива переводятся на новые места или убираются: `AGENTS.md`, `.agents-core/` (`.pi/agents/` — только через `agents:sync`), `.pi/skills/`, `CHANGELOG.md`, код (`domain/src/course/module-courses.dqs.ts`), `conductor/`.

**ФР-4. Тестовое API.**
- `dmg-core/testing` (без фанатизма): `TEST_TRACE`, `testUuid(n)`, выборки фейка репозитория из его памяти по предикату, временный каталог с автоочисткой для контрактных тестов репозиториев.
- Проект: `domain/src/<m>/testing.ts` где нужен; помощники бота (`press`, `buttonsOf`, `findBtn`, `waitMessageFor`, `waitUntil`, `subHandler`, `makeUiApp`, …) — в API `TestBotTransport` и `runners/u7-bot/tests/helpers`; `makeLogger` → `MemoryLogger`.
- Тесты проекта переводятся на хелперы; unit-тесты stories, которые перепишет `dmg-ui`, не трогаются. Открытые `T-DEBT` разобраны.

**ФР-5. Ранние модули `wish`, `peer-review`.** Разбор по образцу `stream`/`course`: модель домена, состав UC, DQS/DCS (классы, расположение), зависимости. Мелкое — правится сразу, крупное — решение Нурболата или долг. Обязательно:
- фейки репозиториев и перевод тестов UC/ER на них (C-DEBT-40 погашен);
- из `peer-review` удалены `QuestionnaireModuleDef` в `dependsOn` и `peer-review-question-pool` (C-07 пересмотрен Нурболатом).

UI модулей не трогается; поведение для пользователя не меняется.

**ФР-5а. Видимость контента** (Нурболат, 2026-11-14). Через API курса — всем только опубликованное, администратору, автору модуля и ментору — всё; из потока (по снимку) — элемент снимка виден участнику независимо от статуса в курсе: студенту (активному, ушедшему, завершившему) — содержимое пройденных хоть раз и текущего выданного шага, остальные — только заголовком (🔒), ментору потока и администратору — всё; неопубликованный элемент при сборке или обновлении снимка пропускается с `warn`; неопубликованное в API курса видит любой ментор (роль), карточка урока и шага для них отмечает статус, если он не «опубликован». Поведение для пользователя меняется (CHANGELOG). ФР-5 и ФР-5а → релиз **v0.3.1**.

**ФР-6. Roadmap, документация и архив.**
- **Ревизия `roadmap.md` и `roadmap/`** с фокусом на упрощение: документ даёт видение — куда растёт продукт, какой функционал будет, как модули взаимодействуют, на какие принятые решения опираются (ссылки на `D-NN`). Детали реализации убираются, остаются общие контуры решений. Исторические и проработанные документы (bot-ui v1–v3, dialog-lifecycle, development-roadmap) — удаляются или в архив, если знание уже в `decisions.md`/гайдах; ещё нужные технические детали — в долг или во вход `dmg-ui`. Треки после перехода (`timestamp-data`, delegation, `dmg-ui` с поглощённым ui-manifests, `dmg-cli`) — в последовательности работ.
- `conductor/architecture/migration.md` — в архив; текущее состояние — в `architecture/index.md`. `agents.md` §9 — режим работы после релиза.
- **Архив треков** — к виду `spec.md` + `summary.md`; технические файлы (plan, slices, inventory, брифы) удаляются после переноса живого знания в `decisions.md`/гайды. Правило — в скилле `conductor-docs` и `workflow.md`.
- documentarian проходит по документам `dmg-core`.

**ФР-7. Вход для `dmg-ui`.** Документ-вход будущей spec: форма ввода по схеме входа UC (wizard), каскад `init` vs конструктор, F-110 (D-72 для `stream`), C-DEBT-41, `@u7-scl/core` (`ui`, `shared`), `bot-ui-session-architecture.md`, автоподключение к группе (транспорт).

## Нефункциональные требования

- `bun run check` зелёный после каждой фазы; число тестов уменьшается только по TST-08 (удалённые дубли — в `summary.md`).
- Живые данные `data/` не трогаются.
- Push и теги (u7-school, `dmg-core`) — только с подтверждения Нурболата.
- **Исполнители:** механические шаги (перевод тестов на хелперы, чистка архива треков, удаления) — Sonnet; Opus — платформа `dmg-core`, решения, приёмка, ревью; Sonnet — `dmg-tech-lead`. DeepSeek с 2026-11-14 не используется (решение Нурболата, план Max). Без фанатизма: короткую правку, где промпт дороже работы, orchestrator делает сам. Расход по фазе — строкой в `summary.md`.

## Критерии приёмки

1. `TODO.md`, `conductor/architecture/debt.md`, `conductor/roadmap/test-bloat.md` удалены; `conductor/debt/` содержит только открытый долг и проходит проверку; вне архива нет ссылок на старые пути и `TR-n`.
2. Проверка долга — в `dmg-core/arch`; в `scripts/` нет своей реализации `checkDebt`/маркеров временности, `arch-check.ts` вызывает пакетную; пакет проверяет себя той же функцией; сценарии старых тестов — в пакете.
3. Хелперы ФР-4 есть в `dmg-core/testing` и используются; в тестах нет локальных повторов `press`, `buttonsOf`, `waitMessageFor`, `makeUiApp`, `makeLogger`, `Trace.fromRequest({ requestId: 'r-1' })`.
4. C-DEBT-40 погашен; у `peer-review` нет зависимости от `questionnaire`; решения разбора ранних модулей записаны; v0.3.1 готов к выкатке.
5. `roadmap.md` и `roadmap/` описывают видение без деталей реализации, у каждой инициативы — опорные решения; архив треков — только `spec.md` + `summary.md`; правило — в `conductor-docs`.
6. Документ-вход `dmg-ui` есть, `roadmap.md` на него ссылается.
