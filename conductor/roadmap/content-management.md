# Управление учебным контентом — видение

Куда растёт контент: автор меняет курсы, не ломая идущие потоки. Принятые решения — D-64, D-65 ([decisions.md](../architecture/decisions.md)); остальное ниже — направление, не решение. Когда дойдёт до работы, трек создаётся отсюда (`conductor-newtrack`).

## Проблема

Курсы правят напрямую в `data/courses/*.json`: операций автора нет, реструктуризация модуля рискует идущими потоками, безопасной «новой версии» контента нет. Нужен API автора и файловый обмен с ИИ-агентами — с едиными правилами на всех уровнях: курс → модуль → проект → урок → шаг.

## Опорные идеи

**Frozen snapshot защищает потоки.** При запуске потока `stream` копирует структуру модуля (проекты → уроки → шаги) в `contentSnapshot`; студент идёт по снимку, модуль не перечитывается. Структурные правки (добавить, убрать, переставить) идут только в новые потоки. Читаются шаги по id, поэтому любой объект, что есть в снимке, должен оставаться доступным.

**Единое правило автора.** Правка с тем же id (edit) — текст и заголовки видны всем сразу (hotfix); структура — только новым потокам (снимок заморожен). Новый id (fork) — копия поддерева, скрытая от идущих потоков.

**`basedOn` — происхождение.** Каждая сущность помнит предка (`basedOn`, у созданных с нуля пусто). Это аудит («какая версия у студента») и основа для связи «тот же модуль» при замене id — где хранить эту связь, см. [course-module-history.md](./course-module-history.md).

**Fork и publish-replace.** Fork создаёт черновик-копию, старое не трогает (окна «нет опубликованного» нет). Publish-replace одной операцией архивирует старое, подставляет новое в родителя и публикует. Без replace — параллельная ветка: оба опубликованы, родитель выбирает.

**archived ≠ hidden.** Черновик скрыт от всех, кроме автора и администратора; опубликованное — в программе, каталоге и снимках новых потоков; архивное выпало из программы; в каталоге его видят автор и администратор, а участник потока — через снимок, независимо от статуса (D-85). Архивирование каскадом: дети уходят вместе с родителем; оркестрирует UC, агрегат архивирует только себя.

**Курс готов к потокам**, когда все модули программы опубликованы; запуск потока это проверяет.

**Связи — по id, без `code`.** Автоподстановка новой версии — работа publish-replace; допуск к следующему модулю по пройденному предку — вопрос к `course` (D-65), не сравнение id у клиента. Этап курса — метка в программе (D-64), не контейнер модулей.

## Import/Export — контур работы автора

Автор работает с папкой файлов (сам или через ИИ-агента), не с JSON:
- **Экспорт** модуля в папку целиком; **импорт** — модуля или выбранных уроков.
- Создание идёт от `plan.md` модуля; обновление сопоставляется с существующим по id, а не по заголовкам (id хранит служебный файл экспорта).
- Импорт всегда через dry-run: отчёт «создать / обновить / без изменений» → утверждение → запись.
- Тексты автора (план модуля и проекта, теория и итог урока) — часть состояния, чтобы экспорт возвращал ровно то, что импортировали; список шагов собирается из шагов, не хранится.
- Режим fork в импорте — следующий шаг после базового.
- Единый `AUTHOR_GUIDE.md` — он же промпт для ИИ-агента. Прямая правка `data/courses/*.json` выводится из практики.

## Порядок работ

1. Операции автора и видимость: `basedOn`, update, remove/reorder, archive; читаемость архивного отделена от членства в программе.
2. Import/Export и воркфлоу автора.
3. Fork и publish-replace на всех уровнях, допуск по цепочке предков, расширение `wish` на историческую принадлежность модуля курсу.
4. Позже: UI автора в боте или вебе — когда появится потребность.

Операции автора пишутся с нуля на Def (старые authoring-команды удалены).

## Есть сейчас

Статусы draft/published/archived у курса, модуля, урока, шага; `contentSnapshot` в `stream` (дерево проектов и уроков с заголовками и `stepIds`; тексты шагов читаются по id — D-85); пререквизит и вопросы к `course` (D-65); этапы-метки (D-64); синхронизация контента идущего потока с текущей версией модуля — UC `previewStreamContentSync`/`syncStreamContent` модуля `stream` (предпросмотр → подтверждение → применение, зачёт шагов позади студента с пометкой `content_sync`), вход админа — `scripts/update-stream-snapshot.ts`; скрипты `distribute-lesson.ts`, `distribute-mentor.ts`. Нет: `basedOn`, операций автора, fork, Import/Export.
