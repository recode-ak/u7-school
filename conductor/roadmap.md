## Карта доменных модулей (метрики и профиль)

Пайплайн «люди взаимодействуют и оценивают друг друга → цифры и тексты паспорта», разрезанный на модули по вопросу, на который отвечает каждый. Сбор фактов, агрегация и предъявление — разные модули; клиент спрашивает, модуль-владелец разруливает (D-65).

| Модуль | Вопрос | Ответственность | Статус |
|---|---|---|---|
| `questionnaire` | Как заполняется анкета? | движок анкет: статусы, likert-шкалы, баллы | ✅ |
| `peer-review` | Что люди сказали друг о друге? | кампании сбора по мероприятиям, текстовые отзывы, затем анкеты в кампании | ✅ отзывы; анкеты — дальше |
| `sessions` | Что произошло? | реестр взаимодействий (парное программирование, код-ревью) → `session.completed` | концепция |
| `dossier` | Что известно о студенте? | агрегация метрик и отзывов по модулю учёбы и по студенту; порог достоверности | заготовка (`modules/dossier`) |
| `passport` | Как предъявить миру? | витрина, PDF+QR, портфолио, рекомендация | концепция |

Смежные: `task` — доставка приглашений и действий человеку; `contribution` — второе измерение профиля «член сообщества».

## Порядок работ

Единый порядок для `dmg-core`, `dmg-ui` и u7-school. Этап не начинается, пока предыдущий не выпущен релизом. Внутри этапа сначала делается нужное в `dmg-core` (отдельный трек и тег пакета), потом сам этап. Чего в списке нет — не делается до этапа 5.

1. **Хвосты.** `timestamp-data` (D-16, D-34), delegation (D-25), релиз `dmg-core` с накопленным.
2. **Архитектура `dmg-ui` и пилот.**
   - Сначала в `dmg-core`: граф и проверки архитектуры принимают расширения от соседнего пакета.
   - Потом spec `dmg-ui`, пакет и один контроллер бота на нём.
3. **Остальные контроллеры.**
   - Сначала в `dmg-core`: генерация документации из графа, форма по схеме входа UC, генератор кода для сторис.
   - Потом переход по контроллерам; в конце удаляются `ui-spec.md` и `@u7-scl/core`.
4. **Хвосты после UI.** Запросы к графу, diff графа между релизами, `dmg-cli`.
5. **Дальше — решается на месте.** Новые фичи (тогда процессы и моделирование фич), web-ui (тогда HTTP и проверка контрактов) или agent-ui (тогда MCP).

Координацию ведёт orchestrator: следит, чтобы инструмент в ядре появился раньше, чем понадобится зависимым. К Нурболату — вопросы по концепциям и проблемы.

### Что нужно от `dmg-core` на каждом этапе

Состояние — по `dmg-core@0.3.1`. «Сверить» — уточняется в spec этапа.

| Этап | Фича `dmg-core` | Сейчас | Зачем |
|---|---|---|---|
| 1 | `DelegateCaller` в транспорте ([caller.md](../node_modules/dmg-core/docs/reference/caller.md) §4) | в работе | агрегат делегирования в `user` |
| 1 | релиз с D-87, D-88; DEBT-1 пакета (`oplog --request`) | не выпущено | чистая база перед `dmg-ui` |
| 2 | общий формат графа (D-78): узел, ребро, виды узлов от пакетов, иерархические `id`, один `graph.json` | граф только доменный, L0–L2 | `dmg-ui` добавляет свои узлы и сшивает экран → UC, а не строит второй граф |
| 2 | `ArchChecker` принимает правила пакета-расширения | правила только свои | проверки UI: `callers` сторис ⊆ `callers` UC, незаявленный переход, UC без UI |
| 2 | публичные примитивы манифестов (`define*`, нормализация, ассерт «вызывает только объявленное») | внутри пакета; сверить | исполнитель сторис по образцу UC ([dmg-ui-entry.md](./roadmap/dmg-ui-entry.md) §3) |
| 2 | подписка внешнего слоя на события со следом вызова | `ApiApp.subscribe()` — только реакции модулей; сверить | сторис `on: Событие`; C-DEBT-41 |
| 2 | текст отказа из `ErrorDef` | сверить | экран отказа по `Result` ([dmg-ui-entry.md](./roadmap/dmg-ui-entry.md) §2) |
| 2 | задел D-82: признак публичности UC и событий, метка масштаба | нет | закладывается вместе с форматом узлов |
| 3 | генерация документации из графа (`docs:domain`); превью экранов даёт `dmg-ui` | нет | условие удаления `ui-spec.md` (D-80) |
| 3 | форма по схеме входа UC: метаданные полей поверх JSON Schema | JSON Schema есть; сверить | мастер создания потока (`mentor` переходит последним); то же ядро — у `dmg-cli` (D-79) |
| 3 | `gen` и `sync` принимают виды и роли от пакетов | только свои | переход контроллеров по образцу |
| 3 | логгер, `serializeError`, `now` — сверка с `dmg-core/app` | дубли в `@u7-scl/core/shared` | условие удаления `@u7-scl/core` |
| 4 | запросы к графу: `ls`, `show`, `impact`, `who-calls`, `--check` (D-81) | нет | агентам и моделированию фич |
| 4 | diff графа между релизами, глоссарий из `label` | нет | журнал изменений домена |
| 4 | `dmg-cli` поверх `dispatchByName` (D-54, C-DEBT-42) | заготовка `~/dev/tools/dmg/dmg-cli` | замена `scripts/call-uc.ts` |
| 5, фичи | процессы (D-83); методика [моделирования фич](./architecture/feature-modeling.md) и роли постановки — в пакет | нет; черновики в проекте | первая сквозная фича — пилот |
| 5, web-ui | HTTP-транспорт (D-17), сравниватель контрактов ([D-DEBT-2](./debt/product.md)) | клиент `ModuleApi` есть, сервера нет | клиент выкатывается отдельно от бэкенда |
| 5, agent-ui | MCP из манифестов (D-18), ресурсы графа | нет | агент над транспортом (D-79) |

Вне порядка, пока не понадобится: смысл в документации и модель решений (D-81), отчёты лога операций поверх графа, лог UI (кроме точки записи на пилоте), развёртывание и масштабы (D-82) — [vision.md](./architecture/vision.md) §7, §9.
