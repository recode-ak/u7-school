# Новые роли агентов — план внедрения

**Назначение:** какие роли добавляются к конвейеру [agents.md](./agents.md) §1, зачем, когда вызываются, как их обкатывают и по каким критериям переносят в пакет `dmg-core`. Нынешние роли (`dmg-domain-author`, `dmg-api-author`, `migrator`, `dmg-reviewer`) отвечают на «как сделать»; новые — на «зачем» (`dmg-user`), «как встраивается в домен» (`dmg-product`), «как устроено технически» (`dmg-architect`), «как нарезать на срезы» (`dmg-tech-lead`) и на узкие риски.

---

## 1. Ключевые правила

1. **Сначала проект, потом пакет.** Новая роль рождается в `.agents-core/roles/` u7-school, проходит пилот на реальных треках и только по критериям §5 переезжает каркасом в `dmg-core/agents/roles/`; проектная часть остаётся в `.agents-core/` (как общий блок сейчас).
2. **Одна роль — один вопрос.** Роль не дублирует `dmg-reviewer` и соседей; пересечение — повод слить роли или сузить промпт.
3. **Только чтение и отчёт** (`read`, `grep`, `find`), кроме тестировщика (пишет тесты). Отчёт — в бриф среза или spec трека, не в чат.
4. **Вызов по триггеру**, а не на каждый шаг (§3). Модель — Sonnet ([agents.md](./agents.md) §10); Opus — только если роль на Sonnet дважды не справилась.
5. **Роль не знает лишнего.** Знания задаются явно (столбец «Знает» §2): пользователь не видит архитектуры, продакт оперирует доменным графом и не видит устройства `dmg-core` и инфраструктуры, архитектор не проектирует домен.
6. **`dmg-*` — агент, имя без префикса — человек** (Нурболат, 2026-11-14). Роль агента процесса — `dmg-<роль>` с рождения, ещё до переноса в пакет: `dmg-product` готовит черновик, человек с ролью `product` решает. Список ролей людей закрыт — [team-roles.md](./team-roles.md) §2. Префикс по-прежнему защищает от конфликтов имён с ролями пользователя, плагинов и других пакетов. Проектные агенты без человека-тёзки (`migrator`, `documentarian`, `methodist`) остаются без префикса: их имён в списке ролей людей нет.

## 3. Место в процессе

- **Постановка** (`conductor-newtrack`): `dmg-user` → `dmg-ux` → `dmg-product` → spec трека; `dmg-architect` — по триггеру: новое хранилище, транспорт, внешняя система, процесс ОС, удалённый UI, заметный объём или время. Каждая роль отвечает на «как» средствами своего слоя: `dmg-ux` — языком UI, `dmg-product` — доменных манифестов, `dmg-architect` — инфраструктуры. Над spec трека — [моделирование фичи](./feature-modeling.md). Для чистого переноса модуля (поведение и устройство не меняются) не вызываются.
- **Обратные петли.** Роль не переделывает выход предыдущей: если домен не позволяет сценарий `dmg-ux`, `dmg-product` возвращает `dmg-ux` причину; если устройство не позволяет доменную модель — `dmg-architect` возвращает её `dmg-product`.
- **Приёмка персоной** (кандидат, решается при внедрении волны 3): после реализации `dmg-user` той же персоной проверяет готовый сценарий против своей истории — снята ли боль.
- **Планирование** (`conductor-newtrack`, после утверждения spec): `dmg-tech-lead` читает spec и код → черновик `plan.md`. Нарезка на срезы решается здесь, один раз; расхождения spec с кодом возвращаются в spec до утверждения плана.
- **Реализация** (`conductor-implement`, срез [agents.md](./agents.md) §3): `dmg-tech-lead` (бриф перед фазой, по коду на текущий момент) → `dmg-test-designer` (red) → автор (green) → гейт → `dmg-reviewer`.
- **Условные проверки после гейта** — по путям в diff: `state`, `*repo.ts`, снимки → `dmg-data-keeper`; Policy, `Caller`, DQS, транспорт и резолвер, oplog и `F.sensitive`, скрипты с `data/`, конфиги → `dmg-security-auditor`. Триггер со временем проверяет `scripts/agent-gate.ts`.
- **После фазы** — `documentarian`, если фаза меняла документы пакета или гайды.

## 5. Критерии годности

Пилот роли (волна 3+) ведётся в `summary.md` трека, раздел «Пилот ролей»: на каждый вызов — повлиял ли отчёт на решение, сколько замечаний принято, правился ли промпт. Роль **годна**, когда за два трека:

1. **Польза:** хотя бы в половине вызовов отчёт изменил spec, бриф, тесты или код — нашёл то, что иначе пропустили бы.
2. **Сигнал, а не шум:** принято не меньше двух третей замечаний; оркестратор не переписывает отчёт заново.
3. **Нет дублей:** замечания почти не пересекаются с `dmg-reviewer` и другими ролями.
4. **Окупается:** работает на Sonnet, отчёт короткий; расход роли меньше, чем стоила бы пропущенная ошибка (оценка оркестратора в разделе пилота).
5. **Стабильна:** последний трек пилота прошёл без правки промпта.

Для **переноса в пакет** дополнительно:

6. **Обобщается:** в промпте нет специфики u7-school — она вынесена в параметры (персона) или общий блок проекта; роль даёт осмысленный отчёт на учебном модуле `dmg-core`.

Не годна после двух треков — роль удаляется или сливается с соседней; решение, несущее знание, — в [decisions.md](./decisions.md) или гайд. Перенос в пакет и смена формата ролей — стратегические (форма API `dmg-core`, [agents.md](./agents.md) §9): только с Нурболатом.
