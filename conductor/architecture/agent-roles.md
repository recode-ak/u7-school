# Новые роли агентов — план внедрения

**Назначение:** какие роли добавляются к конвейеру [agents.md](./agents.md) §1, зачем, когда вызываются, как их обкатывают и по каким критериям переносят в пакет `dmg-core`. Нынешние роли (`domain-author`, `api-author`, `migrator`, `reviewer`) отвечают на «как сделать»; новые — на «зачем» (`user`), «как встраивается в домен» (`product`), «как устроено технически» (`architect`), «как нарезать на срезы» (`tech-lead`) и на узкие риски.

---

## 1. Ключевые правила

1. **Сначала проект, потом пакет.** Новая роль рождается в `.agents-core/roles/` u7-school, проходит пилот на реальных треках и только по критериям §5 переезжает каркасом в `dmg-core/agents/roles/`; проектная часть остаётся в `.agents-core/` (как общий блок сейчас).
2. **Одна роль — один вопрос.** Роль не дублирует `reviewer` и соседей; пересечение — повод слить роли или сузить промпт.
3. **Только чтение и отчёт** (`read`, `grep`, `find`), кроме тестировщика (пишет тесты). Отчёт — в бриф среза или spec трека, не в чат.
4. **Вызов по триггеру**, а не на каждый шаг (§3). Модель — Sonnet ([agents.md](./agents.md) §10); Opus — только если роль на Sonnet дважды не справилась.
5. **Роль не знает лишнего.** Знания задаются явно (столбец «Знает» §2): пользователь не видит архитектуры, продакт оперирует доменным графом и не видит устройства `dmg-core` и инфраструктуры, архитектор не проектирует домен.
6. **Префикс `dmg-*` — у ролей и скилов пакета, у проектных — нет.** Префикс отличает доставляемое `dmg-core sync` (обновляется пакетом, руками не правится) от проектного и защищает от конфликтов имён с ролями пользователя, плагинов и других пакетов (`reviewer`, `architect` — типовые имена). Скил пакета уже `dmg-architecture`; роли пакета получают префикс в шаге переноса в пакет ([migration.md](./migration.md) §5), а при реальном конфликте имён раньше — сразу.

## 3. Место в процессе

- **Постановка** (`conductor-newtrack`): `user` → `ux` → `product` → `architect` → spec трека. Каждая роль отвечает на «как» средствами своего слоя: `ux` — языком UI, `product` — доменных манифестов, `architect` — инфраструктуры. Для чистого переноса модуля (поведение и устройство не меняются) не вызываются.
- **Обратные петли.** Роль не переделывает выход предыдущей: если домен не позволяет сценарий `ux`, `product` возвращает `ux` причину; если устройство не позволяет доменную модель — `architect` возвращает её `product`.
- **Приёмка персоной** (кандидат, решается при внедрении волны 3): после реализации `user` той же персоной проверяет готовый сценарий против своей истории — снята ли боль.
- **Планирование** (`conductor-newtrack`, после утверждения spec): `tech-lead` читает spec и код → черновик `plan.md`. Нарезка на срезы решается здесь, один раз; расхождения spec с кодом возвращаются в spec до утверждения плана.
- **Реализация** (`conductor-implement`, срез [agents.md](./agents.md) §3): `tech-lead` (бриф перед фазой, по коду на текущий момент) → `test-designer` (red) → автор (green) → гейт → `reviewer`.
- **Условные проверки после гейта** — по путям в diff: `state`, `*repo.ts`, снимки → `data-keeper`; Policy, `Caller`, DQS → `access-auditor`. Триггер со временем проверяет `scripts/agent-gate.ts`.
- **После фазы** — `documentarian`, если фаза меняла документы пакета или гайды.

## 5. Критерии годности

Пилот роли ведётся в `summary.md` трека, раздел «Пилот ролей»: на каждый вызов — повлиял ли отчёт на решение, сколько замечаний принято, правился ли промпт. Роль **годна**, когда за два трека:

1. **Польза:** хотя бы в половине вызовов отчёт изменил spec, бриф, тесты или код — нашёл то, что иначе пропустили бы.
2. **Сигнал, а не шум:** принято не меньше двух третей замечаний; оркестратор не переписывает отчёт заново.
3. **Нет дублей:** замечания почти не пересекаются с `reviewer` и другими ролями.
4. **Окупается:** работает на Sonnet, отчёт короткий; расход роли меньше, чем стоила бы пропущенная ошибка (оценка оркестратора в разделе пилота).
5. **Стабильна:** последний трек пилота прошёл без правки промпта.

Для **переноса в пакет** дополнительно:

6. **Обобщается:** в промпте нет специфики u7-school — она вынесена в параметры (персона) или общий блок проекта; роль даёт осмысленный отчёт на учебном модуле `dmg-core`.

Не годна после двух треков — роль удаляется или сливается с соседней; решение фиксируется `TR-<n>` ([debt.md](./debt.md) §6). Перенос в пакет и смена формата ролей — стратегические (форма API `dmg-core`, [agents.md](./agents.md) §9): только с Нурболатом.
