# Роли людей и агентов

**Назначение:** кто в процессе человек, а кто агент, как их отличить по имени, какой вопрос кому из людей задаёт агент и что он делает, когда нужного человека в диалоге нет. От моделей и инструментов не зависит; привязка к u7-school — §6.

> Статус: **черновик на обсуждение** (2026-11-14). Переезжает в `dmg-core/docs/` вместе с [моделированием фичи](./feature-modeling.md).

---

## 1. Ключевые правила

1. **Имя различает человека и агента.** Роль человека — без префикса (`product`), роль агента — `dmg-<роль>` (`dmg-product`). Имя из списка §2 без префикса — всегда человек.
2. **Агент готовит — человек решает.** `dmg-<роль>` отвечает на вопрос черновиком; утверждает человек в роли, которой адресован вопрос.
3. **Вопрос адресован роли, а не человеку.** Агент обсуждает и утверждает пласт только с тем, у кого эта роль заявлена.
4. **Роли заявляет сам человек** — в реестре команды (§3). Роли пересекаются: хватает одного носителя.
5. **Пласт → коммит → проверка роли.** Пласт — вопросы одной роли на одном уровне постановки (§5). Закрыт — решение записано и закоммичено с ролью и именем решившего; затем агент смотрит роль следующего пласта.
6. **Нет нужной роли — передача, а не догадка** (§4). Агент не решает за отсутствующего и не подбирает ответ «как он, скорее всего, сказал бы».
7. **Решение вне роли допустимо, но помечено** (§4): видно, кто решил за кого, пока носитель роли не подтвердит.
8. **Агент не арбитр.** Два носителя роли не сошлись — оба мнения уходят в открытый вопрос, решают люди.

## 2. Роли людей

| Роль | Решает и утверждает | Черновик готовит |
|---|---|---|
| `product` | рамка фичи, истории, поведение для пользователя, состав модулей и агрегатов, словарь, карта треков, spec («что и зачем», критерии приёмки) | `dmg-product`, `dmg-user` |
| `ux` | сценарии, экраны, тексты для пользователя | `dmg-ux` |
| `architect` | связи через границу модуля и `dependsOn`, техническое устройство, форма Def и API платформы, новые правила и решения | `dmg-architect` |
| `tech-lead` | план и нарезка на срезы, эскалации исполнителей, тактика | `dmg-tech-lead` |
| `developer` | код в пределах брифа: пишет сам или принимает работу авторов | `dmg-test-designer`, `dmg-domain-author`, `dmg-api-author` |
| `reviewer` | приёмка фазы, спорные замечания ревью | `dmg-reviewer` |
| `ops` | живые данные, резервные копии, миграции, выкатка, публикация | `dmg-data-keeper` |

Список закрыт: новая роль человека — решение, а не строка в реестре. Проектный агент без человека-тёзки может называться без префикса, если его имени нет в этом списке.

## 3. Реестр команды

- Файл проекта: человек, его идентификатор в системе контроля версий, заявленные роли.
- **Реестра нет** — один человек во всех ролях; пометок и передач нет.
- **Кто в диалоге** — определяет среда (учётная запись системы контроля версий, инструкция сессии). Не определился или его нет в реестре — агент один раз спрашивает роли и дописывает строку его словами.
- **Роль никем не заявлена** — её пласт решает любой, с пометкой «вне роли».
- Роли меняет только их носитель; агент чужую строку не правит.

## 4. Передача и решение вне роли

Перед пластом агент сверяет его роль с ролями собеседника. Не совпало — называет роль пласта и два выхода:

- **Передача.** Агент коммитит сделанное, под пластом записывает «ждёт `<роль>`» и вопросы с вариантами и рекомендацией. Работу, не зависящую от ответа, продолжает; остальную останавливает. Сессия с носителем роли начинается с этих вопросов.
- **Вне роли.** Собеседник явно говорит, что решает за роль. Решение действует сразу и записывается с пометкой `вне роли: <роль> ← <человек>` — в документе пласта и в коммите. Носитель роли при следующем входе получает список таких решений: подтверждает (пометка снимается) или пересматривает.

Сам агент решение вне роли не предлагает как путь по умолчанию и молчаливо его не принимает. Проект может объявить **незамещаемые** роли — для них только передача.

## 5. Пласты по уровням постановки

| Уровень | Пласт | Роль |
|---|---|---|
| Модель фичи | рамка, истории, состав модулей и агрегатов, карта треков | `product` |
| | сценарии | `ux` |
| | связи через границу, `dependsOn` | `architect` |
| Spec | что и зачем, критерии приёмки | `product` |
| | экраны | `ux` |
| | техническое устройство | `architect` |
| План | нарезка на срезы, порядок | `tech-lead` |
| Срез | эскалации исполнителей | `tech-lead`, по коду — `developer` |
| Фаза | приёмка | `reviewer` |
| Данные и выкатка | любое действие с живыми данными, публикация | `ops` |

Бриф среза утверждает оркестратор — пласта человека в нём нет.

## 6. Привязка к u7-school

- Реестр — `conductor/team.md`; пока его нет, Нурболат во всех ролях.
- Идентификатор человека — имя в git (`git config user.name`).
- Незамещаемая роль — `ops`: действия с `data/` и push — только по явному слову носителя ([AGENTS.md](../../AGENTS.md)).
- Проектные агенты без префикса: `migrator`, `documentarian`, `methodist`.
