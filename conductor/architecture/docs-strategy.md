# Стратегия документации

**Назначение:** какая документация бывает, для кого, где лежит и как не устаревает.

---

## 1. Два вида

| | Доменная | Техническая |
|---|---|---|
| **Для кого** | PO, аналитик, LLM | агенты, программисты |
| **Что** | модули, агрегаты, статусы, UC, события, ошибки, права, каскады | архитектура, правила, процессы, решения |
| **Источник** | граф манифестов | вручную + генерация из кода |
| **Обязательность** | обязательна, под неё строится архитектура | ручная часть — обязательна, генерация — по возможности |

## 2. Доменная документация

- Генерируется из графа: `bun run docs:domain` → `docs/domain/` (Markdown + Mermaid) и `docs/domain/graph.json`.
- Структура повторяет граф: `index.md` (L0, карта модулей) → `<module>/index.md` (L1) → `<module>/<aggregate>.md` (L2); каталоги `events.md`, `errors.md`, `use-cases.md`.
- **Коммитится в git.** Diff в PR показывает изменение домена — это ревью для PO. CI проверяет актуальность (`docs:domain --check`).
- Позже `graph.json` питает web-интерфейс и MCP resources — без отдельного источника.
- Качество зависит от `label`/`description` в Def и описаний полей (MAN-01, MAN-02).
- UI-часть (после трека ui-manifests): превью экранов, карта переходов, матрица «роль × экран» — [ui-manifests.md](./ui-manifests.md) §3.

## 3. Техническая документация

**Ручная** — `conductor/architecture/` (этот каталог): решения, слои, правила, процессы. Принципы:
- описывает то, чего нельзя вывести из кода: *почему*, границы, правила;
- не дублирует сгенерированное и код — ссылается на эталон и файлы;
- файлы 30–100 строк, по правилам скилла `conductor-docs`.

**Генерируемая** — `bun run docs:tech` → `docs/tech/`, коммитится:
- граф пакетов и модулей (`dependsOn`, фасады);
- статус каталога правил: какие ID проверяются машинно и где реализация проверки;
- wiring модулей: Def → реализация.

## 4. Где что лежит

| Что | Где |
|---|---|
| Продукт, треки, планы | `conductor/` (product, tracks, roadmap) |
| Архитектура и правила | `conductor/architecture/` |
| UI-гайды бота | `conductor/architecture/ui/` |
| Процедуры (бэкап и т.п.) | `docs/*.md` |
| Сгенерированная доменная | `docs/domain/` |
| Сгенерированная техническая | `docs/tech/` |

## 5. Комментарии в коде

- Def несут документацию в `label`/`description` — JSDoc их не дублирует.
- Комментарий объясняет *почему*, а не *что*. На русском.
