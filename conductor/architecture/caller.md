# Caller — кто вызывает

**Назначение:** абстракция вызывающей стороны для UC, Policy, событий и аудита. Тип — в `@u7-scl/core` (дженерик пользователя замыкает `app`), реализация — трек core-dmg; функция делегирования — отдельный трек модуля user ([migration.md](./migration.md)).

---

## 1. Подтипы

`Caller` — размеченное объединение по `kind`:

| kind | Кто | Субъект для домена |
|---|---|---|
| `guest` | не зарегистрирован; есть только идентификатор канала (tgId) | нет |
| `user` | авторизованный пользователь | он сам |
| `delegate` | заместитель действует от имени другого по делегированию | **тот, кого замещают**; заместитель и `delegationId` — для аудита |
| `system` | Job, ER, межмодульный вызов; источник — FQN | нет; `onBehalfOf?: Caller` — исходный вызывающий, если действие порождено им |

Различие *субъект* (от чьего имени) и *исполнитель* (кто физически) — практика делегирования полномочий (ERP «замещение», OAuth Token Exchange RFC 8693 `act`). Это **не** impersonation: делегирование ограничено сроком и набором прав, отзывается, все действия видны в аудите.

## 2. Ключевые правила

1. Def UC объявляет допустимых вызывающих: `callers: ['user', 'delegate']` (вместо `auth: boolean`). Недопустимый `kind` отсекается до запуска UC (`UNAUTHORIZED`/`ACCESS_DENIED`).
2. Домен и Policy работают с **субъектом** (хелпер `subjectOf(caller)`), а не разбирают `kind` сами.
3. Правило Policy может запретить делегирование: `delegable: false` (передать доверенность дальше, сменить свои персональные данные и т. п.).
4. Конверт события (meta, не payload) несёт `caller`, `cause` (непосредственная причина: запрос, событие или прогон Job) и `correlationId` (вся цепочка от точки входа). Аудит «кто на самом деле» и «из-за чего» строится из meta — домен об этом не знает. `requestId` передаёт транспорт (`appApi.run(uc, input, caller, meta)`); не передал — ядро создаёт сам и пишет `warn` (ERR-07).
5. ER/Job вызывают UC как `system` с `onBehalfOf` из события-причины; Policy видит, что вызов системный.
6. Транспорт строит `Caller` на входе (бот — по tgId и активному делегированию, HTTP — по токену); внутрь UC он передаётся неизменным.

## 3. Делегирование (позже)

Агрегат `Delegation` в модуле user: `from`, `to`, область (роли или правила), `validFrom`/`validTo`, причина, отзыв; события `user.delegation.granted/revoked/expired`. Пока трек не сделан, `delegate` в `callers` объявляется, но транспорт его не строит.
