# Слои и пакеты

**Назначение:** оси приложения, пакеты, кто кого импортирует, что где живёт. Файловая структура и имена — [naming.md](./naming.md); размещение доменной логики — [domain-modeling.md](./domain-modeling.md).

---

## 1. Оси

| Ось | Пакеты | Роль |
|---|---|---|
| **Платформа** | `@u7-scl/core`, `@u7-scl/app` | как приложение реализует предметку: фреймворк (`Result`, `define*`, базовые классы, `F.*`, UoW, граф-движок) и замыкание дженериков приложения |
| **Домен** | `@u7-scl/domain` | чистая предметная область и все контракты |
| **Прикладной слой** | `packages/<m>` | связывает домен с платформой: реализации UC/ER/Job, репозитории, фасады, wiring. **1:1 с `domain/src/<m>`** |
| **Входные адаптеры** | `apps/*` | UI (u7-bot, позже web) и транспорты (http, mcp, cli) |

## 2. Импорты

| Пакет | Может импортировать |
|---|---|
| core | — (платформа DMG вынесена в пакет `dmg-core`, тестовые хелперы — `dmg-core/testing`) |
| `dmg-core` (подпути) | корень — ядро и `define*` (для домена); `/app` — исполнение (UC/ER/Job, модуль, UoW, шина); `/graph` — граф; `/arch` — проверки (D-33) |
| domain | корень `dmg-core` (не `/app`, `/graph`, `/arch`) |
| app | core, domain |
| `packages/<m>` | core, domain, app. Другие модульные пакеты — **нет** (только фасады через резолвер) |
| apps | core, domain, app; логику вызывает через `appApi` и доменный API |

Внутри domain модуль импортирует другой модуль **только** через его `index.ts` и **только** если тот в `dependsOn`. Граф `dependsOn` — DAG: подписчик зависит от публикатора, не наоборот. Если вышестоящему модулю нужно поведение нижестоящего — только через события.

## 3. Доменный API (D-05 … D-07)

Домен един: любой слой пользуется им через API, а не через данные.

1. **Aggregate (Ar)** — бизнес-операции (всегда `Result`), методы-вопросы (никогда `Result`), идентификаторы, события. Не создаёт и не возвращает другой Ar.
2. **Policy** — декларативные права (`rule`, `anyOf`, `allOf`, `hasRole`), решение `allowed | denied(rule, message)`.
3. **DCS** (`DomainCommandService`) — операция над несколькими агрегатами или решение, которое не принадлежит одному Ar. Мутирует, возвращает `Result`.
4. **DQS** (`DomainQueryService`) — вычисления на чтение поверх агрегатов (прогресс, навигация, категоризация). Не мутирует, не зависит от транспорта.

DCS и DQS могут принимать `Loader<T> = () => Promise<T>` — только для условной или дорогой загрузки; по умолчанию получают готовые агрегаты.

**`ReadonlyAr<T>`** — тип Ar без мутирующих методов (выводится по возврату `Result`). Его получают фасады, транспорт, UI.

## 4. Доступ к entity (D-05)

| Кто | Доступ |
|---|---|
| Ar | полный (своё состояние) |
| Рендереры UI (компоненты отображения) | прямой, в т.ч. для реактивности |
| Репозиторий | `Ar.restore(raw)` / `ar.snapshot()`; поля читает только для хранения (ключи, индексы), без бизнес-логики |
| Все остальные (UC, ER, Job, Story, DCS, DQS, Policy, фасады) | **нет**, только доменный API |

Контракты (input/output UC, payload событий) — объявленные схемы, не entity. Output «получить агрегат» = снапшот, который клиент восстанавливает в `ReadonlyAr`.

## 5. Прикладной слой

- **UC** — техническая оркестрация: загрузить Ar → Policy → Ar/DCS → `uow.register(...)`. Сохранение и публикацию событий делает базовый класс после `Ok` (D-15).
- **ER / Job** — та же техничность: реагируют, загружают, вызывают домен, регистрируют в UoW.
- **Репозиторий** — порт объявляется в модульном пакете, принимает и возвращает Ar; только хранение.
- **Фасад** — контракт в domain, реализация в модульном пакете (in-proc сейчас, сетевой позже). Возвращает `Result` и `ReadonlyAr`.

## 6. Входные адаптеры

- **Story** — сценарий UI, логика для любого UI-транспорта; вызывает UC через `appApi.run`, пользуется Ar/DQS.
- **Презентеры/рендереры** — специфика конкретного транспорта (бот, web): форматирование, компоненты.
- **http / mcp / cli** — генерируются из манифестов, см. [transport.md](./transport.md).
- Нет `process.env` / глобального `config` в домене и UI-компонентах: данные школы — через резолвер (`resolve.school`).
