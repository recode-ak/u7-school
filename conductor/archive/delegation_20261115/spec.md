# Spec: `delegation` — делегирование в `dmg-core`

## Обзор

Делегирование — доверие между людьми: A разрешает B действовать от своего имени на срок, с отзывом. Для системы прав заместителя нет: Policy и домен видят замещаемого, `callers` заместителя не перечисляет. Делегирование видит только край платформы: проверка заявки на входе, проверка вида вызывающего, лог операций.

Сейчас в `dmg-core@0.3.2` есть `DelegateCaller`, запись обоих в oplog и ключ отсева повторов, но `delegate` надо перечислять в `callers` каждого UC, а проверки заявки нет. Трек даёт в пакете подключаемую механику и гайд. В u7-school делегирование не добавляется — проект только остаётся готовым к нему. Решение D-25 пакета переписывается.

## Функциональные требования

**Пакет `dmg-core` (v0.4.0)**

- **ФР-1. `callers` без `delegate`.** Словарь `callers` в Def UC — `guest`, `user`, `system`. Заместитель проходит там, где проходит `user`. `kind: 'delegate'` у класса и в логе остаётся.
- **ФР-2. «Только лично».** Признак в Def UC (рабочее имя — `personal`): UC недоступен заместителю, отказ `UNAUTHORIZED`. Признак виден в графе и контракте модуля.
- **ФР-3. «Только чтение».** Признак в `DelegateCaller`; попадает в JSON и в запись oplog. Заместитель с признаком на command UC получает `UNAUTHORIZED`, query проходят. Поле необязательное: старые записи без него читаются. Запись из query UC платформа не запрещает — это запись в `debt.md` пакета, триггер: первое приложение включает «только чтение».
- **ФР-4. Вложенные вызовы.** ФР-2 и ФР-3 проверяются по исходному человеку (`caller.person()`) на каждом UC цепочки — в базовом классе, там же, где `callers`.
- **ФР-5. Правило «query не вызывает command».** `DefChecker`: в `calls` query UC — только query UC; новый ID в `rules.md`, тест.
- **ФР-6. Проверка заявки.** Заявка — три идентификатора: замещаемый, заместитель, делегирование; откуда пришла (токен, сессия бота) — дело транспорта.
  - Порт хранилища делегирований (реализует приложение): по идентификатору вернуть запись — пара, конец срока, отзыв, признак «только чтение». Начала срока нет. Кто выдал — в записи не обязателен, платформа его не читает.
  - Класс проверки: заявка, порт и часы → проверенная запись либо отказ. Проверяет: запись есть, пара совпадает, срок не истёк, не отозвано.
  - `DelegateCaller` строит резолвер приложения: сверяет заместителя из заявки с личностью от транспорта, загружает обоих пользователей; признак «только чтение» берёт из записи, не из заявки. Расхождение личности или отсутствие пользователя — отказ.
  - Резолвер возвращает `Result`, а не бросает исключение. Отказ — новая ошибка ядра вида `unauthorized` с причиной (недействительна, истекла, отозвана, делегирование не подключено). Тихого входа «как сам себе» нет.
  - Проверка выполняется на каждом запросе.
- **ФР-7. Каркас и образец.** Резолвер каркаса `dmg-core init` принимает необязательную заявку. Учебное приложение пакета: реализация порта в памяти и резолвер с заявкой, покрыты тестами. Агрегата делегирования в пакете нет.
- **ФР-8. oplog.** Фильтр `--actor` — действия заместителя. Закрыть DEBT-1 пакета (`--request` по `requestId`).
- **ФР-9. Документы пакета.**
  - Новый гайд «Делегирование: если решили использовать»: что завести в приложении (агрегат в модуле пользователей, UC выдачи и отзыва, реализация порта, заявка в токене или сессии, экраны), рекомендованная запись делегирования (сверх читаемого платформой — кто выдал и причина), два сценария — доверие между людьми и служебный доступ (причина, короткий срок, «только чтение»), какие UC пометить «только лично» (управление делегированием, привязка канала входа, удаление аккаунта, платежи).
  - Правка `concepts/caller.md`, `reference/caller.md`, `reference/transport.md`, `reference/oplog.md`, `rules.md` (MAN-11), `llms.txt`, скила `dmg-architecture`.
  - `decisions.md`: D-25 переписан, новое решение о делегировании.
- **ФР-10. Роль `dmg-access-auditor`** — на время пилота в проекте (рядом с проектными ролями), в пакет переносится после годности (`agent-roles.md` §5); пилот на срезах трека, учёт в `summary.md`, раздел «Пилот ролей».

## Критерии приёмки

1. UC с `callers: ['user']` принимает `DelegateCaller`; Policy получает замещаемого; в oplog — оба идентификатора.
2. UC «только лично» отказывает заместителю — прямо и через вложенный вызов.
3. Заместитель «только чтение»: command — отказ (прямо и от системного вызывающего с таким заместителем), query — успех.
4. Класс проверки и резолвер образца: тесты на каждую причину отказа и на успех; признак «только чтение» берётся из записи; чужой заместитель в заявке — отказ.
5. `DefChecker` отвергает query UC с command в `calls`; `arch:check` u7-school без нарушений.
6. `dmg-core oplog --actor` находит действия заместителя; DEBT-1 удалён из `debt.md`.
7. Каркас `init` и учебное приложение проходят `bun run check` и `bun run e2e` пакета.
8. Гайд есть и ссылается на образец; `docs:covers --strict` без предупреждений; `documentarian` без расхождений.
9. u7-school на v0.4.0: `bun run check`, полный `CI=true bun test`, `arch:check` зелёные, тестов не меньше базовой линии.
10. Записи ФР-12 сделаны; пилот роли описан в `summary.md`.
