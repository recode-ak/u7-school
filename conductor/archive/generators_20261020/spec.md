# Спецификация: generators — `bun run gen` для всех видов артефактов

## Обзор

Трек #2 из migration.md. Скаффолдинг по [naming.md](../../architecture/naming.md) (D-20): структура, пары контракт↔реализация и заготовки тестов создаются командой, а не придумываются агентом. Выполняется после части А `dmg-core-extract`, поэтому генераторы сразу пишут на финальные `dmg-core` и `#core/*`.

## Решения

- Реализация — `scripts/gen/`, Bun и TypeScript, без новых зависимостей. Шаблоны — типизированные функции `(params) → файлы`, а не текстовые `.tmpl`.
- Команда: `bun run gen <kind> <module>[.<aggregate>] <name> [опции]`. Режимы `--dry-run` (по умолчанию печатает план файлов) и `--write`. Существующие файлы **никогда не перезаписываются**, при коллизии генератор падает.
- Пара контракт↔реализация создаётся одной командой: `gen uc` пишет `domain/<m>/<agg>/uc/<name>.uc.ts` и `packages/<m>/src/<agg>/uc/<name>.uc.ts` с одинаковым относительным путём. То же для `er` и `job`.
- **Минимальный пакет `packages/domain`** (package.json `@u7-scl/domain`, tsconfig, biome, пустой `src/index.ts`, подпути экспорта `<m>` и `<m>/state`) создаётся здесь. Наполнение модулями остаётся за треком `domain-package`. Это записывается в spec и plan `domain-package`.
- Корни настраиваются (`--domain-root`, `--packages-root`) — для тестов во временном каталоге.
- Правки существующих файлов только по маркерам: `// gen:exports` в `index.ts` и `// gen:defs` в `<m>.module.ts`. Если маркера нет — генератор печатает строку для ручной вставки и не падает.

## Функциональные требования

**Ф1. Виды артефактов.**
- `module <m>`: домен (`<m>.module.ts`, `<m>.facade.ts`, `index.ts`) и прикладной слой (`packages/<m>`: `module`, `facade`, каркас).
- `aggregate <m>.<agg>`: `state`, `ar`, `policy`, `events`, `errors`, а также `repo` (порт) и `infra/<agg>.json-repo.ts`.
- `uc`, `er`, `job`: пары, как описано выше.
- `dcs`, `dqs`: `<topic>.dcs.ts` / `<topic>.dqs.ts`.
- Имена: kebab-case на входе, классы и Def по таблице §4 `naming.md`, сокращения `Ar/Uc/Er/Job/Dcs/Dqs/Repo`.

**Ф2. Заготовки тестов.** Рядом с каждым файлом создаётся `<file>.test.ts` с рабочим минимальным тестом по testing.md. Тест проходит без правок.

**Ф3. Валидация ввода.** Проверяются kebab-имена, существование модуля и агрегата для `uc/er/job`, уникальность имён и FQN событий. Ошибки понятные, на русском.

**Ф4. Комментарии-заготовки.** В сгенерированных файлах `TODO` помечает только места, которые заполняет автор. Ссылки на ID правил ([rules.md](../../architecture/rules.md)) в шапках не дублируются.

**Ф5. Интеграция.** `bun run gen` в `package.json`; `scripts/gen/README` не создаётся, документация — в `conductor/architecture/naming.md` (раздел «Генераторы») и `agents.md` §2. В ролях `domain-author`, `api-author`, `migrator` в `.agents-core/roles` добавляется «создавай через `gen`»; `agents:sync` обновляет `.claude/`/`.pi/`.

## Нефункциональные требования

- TDD: тесты генераторов пишутся до реализации.
- Идемпотентность: повторный запуск без `--force` ничего не ломает.
- Результат стабилен (детерминированный порядок и форматирование, проходит `biome`).

## Критерии приёмки

1. Тест `gen-e2e`: во временном каталоге генерируется срез (модуль → агрегат → uc → er → job → dcs → dqs); `check` и `arch:check` на нём зелёные **без ручных правок**.
2. Все пути и имена совпадают с `naming.md` (проверяется тестом на снапшотах).
3. Коллизия файла → ошибка, ничего не записано (атомарность: сначала план, потом запись).
4. `bun run check` монорепо зелёный.
5. Документация и роли агентов обновлены.

## За рамками

- Генераторы UI (`ui-manifests`).
- Генерация доменной логики (тела методов, правила) — только заготовки.
- Гайды по видам артефактов с эталоном — после `golden-wish`.
- Перенос существующих модулей в `packages/domain` (`domain-package`).
- Генерация `define*` для HTTP/mcp-потребителей графа.
