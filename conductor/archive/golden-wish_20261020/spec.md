# Спецификация: golden-wish — эталонный перевод `wish` на Def

## Обзор

Трек #4 из migration.md. Модуль `wish` (домен `packages/domain/src/wish`, прикладной слой `packages/wish`) переводится с механически перенесённого legacy-кода на Def, `Result`, Policy, entity-правило, UoW и `F.timestamp`. Это **эталонный срез**: по нему агенты пишут остальные модули. Гайды по видам артефактов пишутся по ходу трека, сразу после каждого вида, и уточняются по итогам ручной проверки фазы.

## Решения

- **Полный срез.** Домен и прикладной слой (4 UC, 4 ER, JSON-репозиторий) одним треком. Не делится на два: эталон требует единого набора решений, а migration.md и `dmg-core-extract` ссылаются на один трек. **Размер контролируется фазами:** одна фаза — один вид артефакта, обзор и гайд до перехода к следующей; остановиться можно после любой.
- **Формат данных не меняется.** Схемы на `F.timestamp` читают ISO-строку и число, пишут число (migration.md §4). Пакетная миграция `data/wish/` и удаление «чтения строки» — трек 7. Трек не пишет в `data/` ни скриптами, ни вручную; репозиторий проверяется на `DB_DIR=./data/fixtures`.
- **Долги.** Гасятся DEBT-21, DEBT-22, DEBT-24. Общие DEBT-1, DEBT-2 остаются за `user`; для wish тип резолвера берётся из платформы. Barrel DEBT-23 остаётся до последнего трека миграции. Реестр — debt.md, ID `DEBT-<n>` (отдельно от решений `D-NN`).
- **Совместимость.** Остальные модули зависят от `wish` через `@u7-scl/domain/wish` и barrel `@u7-scl/wish/domain` (DEBT-23). Публичное поведение фасада не меняется.
- **Исполнители.** Orchestrator + Нурболат; срезы раздаются `migrator`/`domain-author`/`api-author`, `reviewer` проверяет перед коммитом ([agents.md](../../architecture/agents.md)).
- **Гайды — вариант А.** В проекте гайды ведутся в `conductor/architecture/guides/` с эталоном `wish`. При выносе в `dmg-core` (Фаза 5 `dmg-core-extract`) они переезжают в `docs/guides/` пакета и ссылаются на учебный модуль пакета; `wish` остаётся эталоном проекта.

## Функциональные требования

**Ф1. Домен.** `wish` описан через `define*`: state, Ar (`Ar.create(): Result`, `Ar.restore()`, `snapshot()` только для репозитория), события со схемой и FQN, ошибки в домене, Policy с `denyMessage`, entity-правила, DCS/DQS вместо смешанного Ds (если нужно, решается в брифе). Фасад возвращает `Result` и `ReadonlyAr`. Нет импортов `@u7-scl/core` и `@u7-scl/app` в `domain/wish`, нет `v.isoDateTime`.

**Ф2. Прикладной слой.** UC и ER реализованы по Def (`*FromDef`), модуль собран картой Def → класс. Запись идёт через UoW, один UoW — один модуль, межмодульные изменения только через фасад/событие. Отказы возвращаются как `Result`, не `throw*`. Сбой ER логируется и попадает в журнал сбоев, а не гасится `console.error`. Job в модуле нет.

**Ф3. Сосуществование.** `appApi.run` и `appApi.execute` работают для wish одновременно. Вызывающие stories и UI wish не ломаются. Базовая линия тестов (3211 pass, 0 fail) не падает; `bun run check` и `arch:check` зелёные после каждой задачи.

**Ф4. Гайды эталона.** Один файл на вид артефакта, 40–80 строк:

| Вид | Фаза |
|---|---|
| state | 1 |
| aggregate | 2 |
| events | 3 |
| errors | 4 |
| policy | 5 |
| repo / dcs / dqs | 6 |
| facade | 7 |
| use case (command и query) | 8–9 |
| event reaction | 10–11 |
| module | 12 |

Формат гайда: (1) когда применять, (2) команда `bun run gen …`, (3) эталон — путь к файлу `wish` (ссылка, не вставка кода), (4) чеклист ID из [rules.md](../../architecture/rules.md), (5) типичные ловушки из ревью фаз, (6) как тестировать. Гайд пишется сразу после кода вида и правится по ручной проверке фазы, чтобы код и гайд смотрелись вместе.

Без отдельного гайда: Job (эталона нет — stub «эталона нет, ориентир — manifests.md; гайд появится в первом модуле с Job»), тесты (testing.md), общие поля `F.*`/`shared/` (manifests.md §3), генераторы ([naming.md](../../architecture/naming.md) §5), UI (трек ui-manifests).

Контрактный тест (в `check`): ссылки гайдов на эталонные файлы и ID правил живые.

**Ф5. Входной долг.** Погашение DEBT-21, DEBT-22, DEBT-24 и DEBT-31 — маркеры и записи debt.md синхронно (`arch:check`). Новые долги — с DEBT-32.

## Нефункциональные требования

- Поведение wish сохраняется: переносятся существующие 40 тестов домена и тесты `packages/wish`; перепроектирование — новыми тестами по TDD (red → запуск → green).
- Новых зависимостей нет.

## Критерии приёмки

- В `domain/wish` и `packages/wish` нет `throw*` для штатных отказов, нет `new Ar`, нет импортов `core`/`app`.
- DEBT-21, DEBT-22, DEBT-24 погашены.
- Все применимые ID [rules.md](../../architecture/rules.md) проходят `arch:check`; правила `review` — отчёт reviewer без блокирующих замечаний.
- Гайды Ф4 написаны, контрактный тест ссылок зелёный.
- Данные не затронуты: `git status data/` чист.
- migration.md обновлён: пункт 4 ✅, снят блок с Фаз 4–6 `dmg-core-extract`.
