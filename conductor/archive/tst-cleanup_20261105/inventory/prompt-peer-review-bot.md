# Инвентаризация тестов `peer-review-bot` (трек tst-cleanup_20261105, Ф2)

Ты работаешь в репозитории u7-school (worktree ветки `tst-cleanup`). Задача — **только чтение кода и запись одного файла отчёта**. Все тексты — на русском.

## Цель

Мы ищем «пустые» и околопустые по полезности тесты: тесты, удаление которых не уменьшит защиту от реальной ошибки в проде. Закономерности уже найдены на модулях `wish`, `stream`, `questionnaire` — **Б-1…Б-14** в `conductor/roadmap/test-bloat.md` §2 (прочитай целиком, с признаками поиска). Правила — `node_modules/dmg-core/docs/reference/testing.md` §3, §5, §5.1 (TST-08, TST-09), `conductor/architecture/ui/bot-test.md` §2 п. 5, раздел «Решения» в `conductor/tracks/tst-cleanup_20261105/spec.md`. Образец уровня оценок — `conductor/tracks/tst-cleanup_20261105/inventory/questionnaire-bot-delete.md` (принятая таблица `questionnaire`; прочитай начало и итог, целиком не нужно).

Кандидатов относи к **Б-ID**. Новая закономерность, не подходящая ни под одну Б, — номер **Н1, Н2…** с полным описанием (признак, почему бесполезен, примеры). Ничего не удаляем.

## Область

- тесты бота про взаимные отзывы: `runners/u7-bot/src/controllers/peer-review/**/*.test.ts`, `runners/u7-bot/tests/e2e/peer-review-*.e2e.test.ts` (база 131, все зелёные; прогон: `cd runners/u7-bot && bun test src/controllers/peer-review tests/e2e/peer-review`). `src/controllers/school/stories/school-reviews.story.test.ts` — экран школы, не в области: только читать для поиска повторов. Особое внимание: повтор сценария между story-тестом, controller-тестом и e2e (в т.ч. `peer-review-smoke` против остальных e2e); тесты текста/разметки клавиатуры и рендера (`review-render.test.ts`); файлы-паспорта экранов (Б-14); проверки того, что гарантирует платформа `dmg-core`/UI-ядро.

Чтобы понять, что тест защищает, читай проверяемый исходник. Тесты платформы `dmg-core` смотри в `node_modules/dmg-core/src` только чтобы понять, не проверяет ли наш тест то, что уже гарантирует платформа.

## Как оценивать каждый `it`/`test`

Для каждого задай вопрос: **«какая реальная ошибка в коде модуля уронит этот тест и только его?»** Если такой ошибки нет или её ловит другой тест — тест кандидат. Будь строгим, но честным: если сомневаешься — «полезен».

## Результат

Создай файл `conductor/tracks/tst-cleanup_20261105/inventory/peer-review-bot.md` (только его, больше ничего не создавай и не меняй):

1. **Сводка** — число тестов по файлам и оценкам.
2. **Закономерности** — по каждой встреченной Б-ID: число случаев и 2–3 примера `путь:строка`; новые Н-ID — с полным описанием.
3. **Кандидаты** — таблица только по тестам с оценкой «сомнителен» или «пуст»: `путь:строка` (где начинается `it(`/`test(`) | имя теста | Б-ID / Н-ID | где покрыто (`путь:строка` начала конкретного `it`, или «нигде» с фразой почему) | что делать (удалить / слить / переписать / перенести).
4. **Полезные тесты** — одной строкой на файл: «файл — N тестов, полезны, защищают …».
5. **Открытые вопросы** — то, что требует решения orchestrator (до 5 пунктов).

Каждая ссылка «где покрыто» указывает на конкретный `it`, который сам не кандидат.

## Не трогай

Любой код, тесты, `conductor/` (кроме своего файла), `data/`, `node_modules/`. Не запускай seed, не коммить. Запускать `bun test` по области можно. Другие файлы `peer-review-*.md` пишутся параллельно — не читай и не пиши их.

## Отчёт

В ответе: путь к файлу, число тестов, число кандидатов, распределение по Б-ID, новые Н-ID одной строкой каждая.
