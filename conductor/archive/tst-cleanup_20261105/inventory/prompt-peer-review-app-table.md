## Решения, которые обязательны (общие)

- **Схемы (Б-8):** удаляются тесты приёма/отказа полей платформы. Остаются: своя логика схемы (`refine`/`transform`), отказ прежних форм записи, схема state, разбираемая при чтении файла, — одной таблицей «валидно/невалидно» на схему.
- **Паспорта Def (Б-7):** удаляются все. На модуль остаётся **один** тест состава — доменный `domain/src/peer-review/peer-review.module.test.ts:8` (UC, Job, `dependsOn`; если ему чего-то не хватает — «переписать»).
- **Тексты `label`/`denyMessage` ошибок** не тестируются (TST-09). Одиночные `expect` на них внутри полезных тестов — раздел «Остающиеся проверки `label`» (файл:строка `expect`); снимаются в этом же срезе.
- **Одно правило на двух уровнях (Б-1):** правило проверяет владелец (Ar / DCS / DQS / Policy домена). У UC модуля остаются: один сквозной сценарий на UC и то, что делает только UC (загрузка, свой `*_NOT_FOUND`, запись в UoW, публикация); Policy-отказ UC — **один** кейс на модуль, не удаление всех.
- **Policy домена:** каждое правило — allowed и denied (`testing.md` §3); «без субъекта — denied» — как в `questionnaire-domain-delete.md`.
- **Бот:** integration — связка слоёв, e2e — пользовательская история. Тесты, красные сейчас из-за `course-dmg` (TR-57 в `conductor/architecture/debt.md`), **не удалять** — «отложить до course-dmg».
- Каждое удаление — только если указано, где покрыто то, что тест мог бы поймать. «Нигде» допустимо только для Б-9/Б-11/Б-12/Б-13 — с одной фразой.
- **Б-13 (мёртвый экспорт):** тест не трогаем — `отложить: удалить с кодом`.
- **Направление Б-1:** удаляется копия **выше** владельца. Доменный тест правила (Ar/DCS/DQS/Policy/rules) нельзя удалять со ссылкой «покрыто UC модуля» — наоборот, удаляется копия в UC. Исключение — доменные тесты Def UC (`domain/src/peer-review/**/uc/*.test.ts`, `er/*.test.ts`): это паспорта/схемы (Б-7/Б-8), поведение держит модуль.
- Ссылка «где покрыто» в другой уровень ведёт только на тест, который инвентаризация того уровня (`peer-review-<уровень>.md` §4) считает полезным. Внимание: в `peer-review-domain.md` часть путей записана с ошибкой уровня (`modules/peer-review/src/review/review.ar.test.ts` — такого файла нет, Ar-тесты в `domain/src/peer-review/`) — проверяй каждый путь.
- Новые Н-ID инвентаризации в таблице записывай как `Н<n>-app` (у каждого уровня своя нумерация).
