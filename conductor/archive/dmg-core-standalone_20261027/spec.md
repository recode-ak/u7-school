# Спецификация: dmg-core-standalone_20261027

## Обзор

Пакет `dmg-core` становится самодостаточным для старта нового проекта: агент только по документации и командам пакета разворачивает проект в одном из двух профилей — **single** (один пакет) или **monorepo** (пакет домена, прикладные пакеты модулей, пакет приложения, раннеры). Затем пакет выносится в отдельный локальный git-репозиторий (`~/dev/tools/dmg/dmg-core`), u7-school подключает его как внешнюю зависимость. Без публикации и пуша (правило «не пушить до релиза»).

Продолжение трека [dmg-core-extract_20261020](../../archive/dmg-core-extract_20261020/summary.md): его Ф6 «Готовность к выносу» оставила вынос чек-листом после релиза; здесь — самодостаточность для нового проекта и локальный вынос, публикация по-прежнему после релиза.

**Почему сейчас:** в недалёком будущем — новый проект по контуру u7-school. Анализ 2026-10-27: для профиля single документации хватает, для monorepo — нет: не описаны сборка приложения (D-04), каркас монорепо, карта плагинов biome, `check` проекта. В u7-school DMG-модули собираются в раннере (`runners/u7-bot/src/create-dmg-modules.ts`), `@u7-scl/app` — legacy: «корень сборки» для DMG фактически не решён.

## Функциональные требования

1. **Корень сборки — решение D-NN пакета.** Где собирается приложение (`AppContext`, модули, `ModuleFacades` по `dependsOn`, outbox/inbox, oplog, logger, резолвер `Caller`) и что остаётся раннеру. Рекомендация: пакет приложения экспортирует фабрику приложения из окружения; раннер — точка входа, транспорт и окружение.
2. **Учебное приложение** в `src/testing/example`: модули `todo` и `users` собраны по решению п. 1, плюс минимальный in-proc раннер (CLI-команда → UC через модуль), с тестами.
3. **`dmg-core init --profile single|monorepo`** — каркас проекта (без `--profile` — прежнее поведение, только доставка):
   - **single:** `package.json` со скриптами `check`/`arch:check`, tsconfig, `biome.json` с картой плагинов на `src/domain` и `src/app`, `dmg-core.json`, `arch-check.ts` на `GenLayout`;
   - **monorepo:** корневой workspace, пакет домена (`exports` `./*/contract`, `./*`), пакет приложения, каталоги `modules/` и `runners/`, секция `gen` с `domainImport`, карта плагинов по пакетам, корневой `check`;
   - существующие файлы не перезаписываются (как `gen`).
4. **`gen module` в профиле monorepo** создаёт и пакет прикладного модуля (`package.json`, tsconfig) — сейчас руками (`naming.md` §5).
5. **Документация:** гайд `docs/guides/project.md` (оба профиля, что создаёт `init`, как растёт проект), гайд сборки приложения `docs/guides/app.md` на учебном приложении, README — быстрый старт обоих профилей, `llms.txt`, скил `dmg-architecture`, карта «плагин → каталоги слоёв» в `rules.md`.
6. **Локальный вынос:** `git subtree split` → `~/dev/tools/dmg/dmg-core`; u7-school — зависимость не `workspace:*` (`link:`/`file:`, выбор в треке); удаление `platform/dmg-core`, адаптация `extract:check`; ссылки документации проекта → `node_modules/dmg-core/…`; актуализированный чек-лист публикации.
7. **Поставка:** сравнение npm / приватный registry или scope / git с рекомендацией; решение — при публикации (после релиза).

## Критерии приёмки

- `consumer-e2e.sh` проходит оба профиля: `init --profile` → `gen module/aggregate/uc` → сборка приложения → раннер вызывает UC → `check` зелёный.
- **Агентная приёмка:** субагент в пустом каталоге без доступа к u7-school поднимает monorepo с модулем и вызовом UC только по документации пакета; найденные пробелы закрыты, повторный прогон чистый.
- u7-school работает на вынесенном пакете из `~/dev/tools/dmg/dmg-core`, `bun run check` зелёный.
