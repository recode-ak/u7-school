# Инвентаризация тестов типов `dmg-core` (трек type-tests_20261111, Ф1)

Задача — **только чтение кода и запись одного файла**. Все тексты — на русском. Код и тесты не меняй.

Пакет: `~/dev/tools/dmg/dmg-core` (дальше — «пакет»). Пути в списке — от корня пакета.

## Прочитай целиком, одним вызовом

1. `conductor/tracks/type-tests_20261111/inventory/rules.md` — выжимка правил и вердиктов. Других гайдов не читай.
2. `conductor/tracks/type-tests_20261111/inventory/list.md` — механический список: 135 случаев, номер, файл:строка, вид, имя теста, фрагмент.

Читай связанные файлы пачкой (несколько файлов одним вызовом), не перечитывай уже прочитанное. Обходи список по файлам: один тестовый файл — одно чтение.

## Что сделать по каждому случаю

1. Прочитай тест вокруг строки.
2. **Позитивный (`pos`):** найди, использует ли рабочий код пакета тот же вывод: `grep -rn` по `src/` с исключением `*.test.ts` (`--exclude='*.test.ts'`), включая `src/testing/example/`. Пиши конкретное место использования (`файл:строка`) или «нет».
3. **`expect-error`:** определи, что запрещает строка под маркером — гарантию типа или обход типов ради рантайм-ветки (тогда под строкой ждут результат/ошибку в рантайме: `expect(...)`, `.rejects`, `toThrow`). Отметь, есть ли пояснение после маркера и одна ли ошибка возможна в строке под ним.
4. Поставь вердикт по `rules.md`.

## Результат

Файл `conductor/tracks/type-tests_20261111/inventory/table.md`:

1. Таблица — **ровно 135 строк**, по строке на случай, в порядке и с номерами из `list.md`:
   `#` | `файл:строка` | вид (`позитивный` / `негативный` / `рантайм-ветка`) | гарантия (одна фраза: что проверяет) | использование (`файл:строка` в рабочем коде или `нет`; для негативных — `—`) | вердикт (`удалить` / `оставить` / `оставить, сузить` / `оценить: оставить` / `оценить: удалить` / `спорно`) | причина (одна фраза; для «оценить: удалить» — где покрыто, `файл:строка` начала `it`)
2. Под таблицей — «Четыре гарантии»: для каждой из четырёх гарантий из `rules.md` — номера строк таблицы, которые её держат. Нет ни одной — так и напиши.
3. Итог: сколько каждого вердикта; сколько `it` станут пустыми после удаления (имя файла:строка `it`) — такие `it` удаляются целиком.

Проверь скриптом в конце: в таблице 135 строк данных, у каждой есть вердикт, номера 1…135 без пропусков.
