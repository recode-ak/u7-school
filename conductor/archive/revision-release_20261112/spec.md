# Spec: Ревизия перехода по `v0.2.6` и релиз `v0.3.0`

## Обзор

Переход на DMG завершён (трек `legacy-removal`, 2026-11-12). Условие релиза (`migration.md` §1) — ревизия: сверка поведения с релизом `v0.2.6` (worktree `../u7-school-v0.2.6`, только чтение), разбор тактических решений `TR-<n>` и открытых `DEBT-<n>`, перепроектирование по решениям Нурболата; затем — тег `v0.3.0` и push. Выкатка на прод — вне трека, трек готовит для неё контекст.

## Функциональные требования

- **ФР-1. Каталог сценариев.** Перечень пользовательских сценариев бота `v0.2.6` по ролям (гость, студент, ментор, админ, проактив/Job, события мессенджера) — из `ui-spec.md` контроллеров, stories, команд и Job эталона.
- **ФР-2. Кодовая сверка.** Для каждого сценария ФР-1 — сравнение кода обеих версий, статус: «совпадает / изменилось (намеренно | регрессия) / пропало». Намеренное — со ссылкой на трек, `D-NN` или TR.
- **ФР-3. Покрытие e2e и ручная проверка.** Запускается только текущая версия; старая — только как код и `ui-spec.md`.
  - Для каждого сценария ФР-1 — e2e-тест текущего бота, который проходит его путь (столбец «e2e» в таблице ФР-2); непокрытые пути — red e2e-тесты в ФР-6.
  - Чек-лист ключевых сценариев для ручной проверки Нурболатом на текущем боте и текущем тестовом мире (`bun run dev:fixtures`, не живые `data/`); находки — в таблицу ФР-2.
- **ФР-4. Триаж TR и DEBT.** Каждая запись `TR-<n>` с полем «Пересмотреть» и каждый открытый `DEBT-<n>` — в одну группу:
  - **«оставить»** — решение верное, переносится в документацию (гайд / `decisions.md`), TR закрывается;
  - **«погасить тактически»** — правка в этом треке без стратегических решений;
  - **«решение Нурболата»** — карточка: суть, варианты, рекомендация.
- **ФР-5. Обязательные пункты ревизии** (`migration.md` «Дальше») — как «решение Нурболата»:
  - штатный отказ «гость без `/start`» и `includes` ERR-01 на `modules/*/src` (TR-68);
  - аудит контрактов после D-69: TR-43 С1, TR-50 (6), проход по `domain/src/*/contract.ts`.
- **ФР-6. Исправления.** В треке — недостающие e2e (ФР-3), регрессии из ФР-2/ФР-3, группа «погасить тактически», решения Нурболата небольшого объёма. Крупное перепроектирование — кандидатами `[?]` в `tracks.md` с заготовкой в `conductor/roadmap/`.
- **ФР-7. Релиз.**
  - секция `## [0.3.0]` в `CHANGELOG.md` (свести `[Unreleased]` + итоги перехода; Added / Changed / Fixed / Migration);
  - `bash scripts/release.sh 0.3.0 "<описание>"`: гейт `check`, коммит версии, тег, `git push origin main --follow-tags`.
- **ФР-8. Контекст выкатки.** Push релиза — с dev-машины (ФР-7). Выкатка — отдельной сессией на prod-машине: `git pull` и шаги по документу (остановка прода → бэкап → миграции → запуск новой версии). Документ для выкатки: порядок шагов на сервере, миграции данных (`users.json` — `migrate-users-drop-student`, `questionnaires.json`), бэкапы, откат, переменные окружения, остатки старых каталогов `apps` и `packages` (из `[Unreleased]`). Источник — `migration.md` «Чек-лист релиза» и отчёты `dmg-data-keeper`. Сама выкатка не выполняется.

## Нефункциональные требования

- `../u7-school-v0.2.6` — только чтение, не запускается.
- Живые `data/` не трогаются; ручная проверка — только на тестовом мире текущего кода.
- Исправления — по TDD (red → green).
- Итоговый гейт `bun run check` зелёный, не хуже базовой линии `legacy-removal/summary.md`.

## Критерии приёмки

1. Каталог сценариев и таблица сверки лежат в треке; у каждого сценария статус, у каждого «изменилось» — обоснование или исправление.
2. У каждого сценария есть e2e-тест текущего бота (или явное решение Нурболата, почему нет); чек-лист ручной проверки передан Нурболату, находки внесены.
3. Все TR с «Пересмотреть» и открытые DEBT имеют группу; карточки «решение Нурболата» решены.
4. TR-68 и аудит контрактов — решены и выполнены либо вынесены кандидатами.
5. Регрессий без решения нет.
6. Крупные решения — кандидатами `[?]` в `tracks.md` с заготовками.
7. `CHANGELOG.md` с `[0.3.0]`, тег `v0.3.0` создан и запушен.
8. Документ контекста выкатки готов, `migration.md` ссылается на него.

## За рамками

- Выкатка на прод, миграции живых данных, рестарт pm2.
- Трек `timestamp-data` и пограничные `throw*` (после релиза, TR-68).
- Крупное перепроектирование (только кандидатами).
- Новая функциональность.
