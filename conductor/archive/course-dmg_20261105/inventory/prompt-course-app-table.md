## Общие решения

- **Схемы (Б-8):** удаляются тесты приёма/отказа полей платформы (`F.uuid`, `picklist`, `variant`, `required`). Остаются: своя логика схемы (`refine`/`superRefine`/`transform`), отказ прежних форм записи, схема state, разбираемая при чтении файла, — **одной таблицей «валидно/невалидно» на схему** (`слить в` первый остающийся тест схемы, каждый слитый кейс — строка таблицы).
- **Паспорта Def (Б-7):** удаляются все. Тест состава модуля — `domain/src/course/course.module.test.ts:31` (список UC и `dependsOn`; если `dependsOn` нет — `переписать`); реализация — `modules/course/src/course.module.serves.test.ts`.
- **`label`** ошибок не тестируется (TST-09): одиночные `expect` на `label` внутри полезных тестов — разделом «Остающиеся проверки `label`» (файл:строка `expect`) — их снимут.
- **Б-1:** правило проверяет владелец (Ar / DCS / DQS / Policy / state домена). У UC модуля остаются: один сквозной сценарий на UC и то, что делает только UC (загрузка, Policy-отказ, своя ошибка, запись в UoW).
- **Б-13 (мёртвый код):** действие `удалить с кодом` — тест удаляется вместе с кодом в шаге применения; в колонке «где покрыто» — какой код удаляется и что `grep` импортов вне теста пуст.
- Каждое удаление — с указанием, где покрыто то, что тест мог бы поймать. «Нигде» допустимо только для Б-9/Б-11/Б-12/Б-13/Б-15/Б-17 — тогда одна фраза почему.
- **Не трогать (§6):** строгое чтение `courses.json` в репозитории (инварианты программы, отказ старого формата), legacy ISO / даты без секунд — остаются, строкой «оставлено (§6)» в разделе итога.
