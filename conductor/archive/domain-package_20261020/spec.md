# Спецификация: domain-package — наполнение `@u7-scl/domain`

## Обзор

Трек #3 из migration.md. Каркас `@u7-scl/domain` создан в треке `generators`. Здесь в него механически переносятся domain-слои модулей снизу вверх: `user` (+ `User` из `app`) → `course` → `questionnaire` → `stream` → `wish` → `peer-review` → `dossier`. Поведение не меняется (strangler, migration.md §1). Перепроектирование на Def, `Result` и Policy относится к `golden-wish` и последующим трекам.

**Конечная цель миграции** — чистый домен на новой архитектуре (D-03: чистый, синхронный, зависит только от `dmg-core`). Этот трек даёт правильную **топологию** (весь домен-код живёт в одном пакете по `dependsOn`), а не чистоту. Временные нарушения чистоты допускаются, но только учтённые.

## Решения

- **Механика сначала, чистота потом.** Файлы переносятся как есть (`git mv`, история сохраняется). Импорты `@u7-scl/app` и `@u7-scl/core` внутри перенесённого кода временно разрешены.
- **Каждое временное нарушение — учтённый долг.** Долг имеет ID `D-<n>` в debt.md (место, причина, кто и когда погашает, критерий снятия). В коде он помечен `// DEBT(<id>)`, а в `arch:check` занесён в allowlist.
- **Allowlist только уменьшается.** Новая запись допустима лишь вместе с записью в `debt.md`. Проверка падает, если в allowlist есть запись без маркера в коде (долг погашен, а запись осталась) или если маркер в коде есть, а записи в allowlist нет.
- **Реэкспорты в старых пакетах.** `packages/<m>/src/domain/index.ts` реэкспортирует из `@u7-scl/domain/<m>`. Потребители не трогаются. Каждый реэкспорт — долг (один на модуль), его снимает последний трек миграции (критерий завершения §5).
- **`User` из `app`.** Переносится в `domain/user`, в `app` остаётся реэкспорт (долг).
- **Зависимости между модулями — строго по `dependsOn`** (DAG): `user` ← `course`, `questionnaire` ← `stream` ← `wish`, `peer-review`.
- **Исполнитель** — агент `migrator`, по брифу на модуль. Модуль — отдельный коммит, гейт `bun run check` зелёный после каждого.

## Функциональные требования

**Ф1. Перенос.** Для каждого модуля `<m>`: domain-код и его тесты оказываются в `packages/domain/src/<m>/`, история git сохранена. Публичные подпути `@u7-scl/domain/<m>` (API и Def) и `@u7-scl/domain/<m>/state` (схемы entity, только для рендереров UI) — по [naming.md](../../architecture/naming.md). В `packages/<m>/src/domain/` остаётся только barrel-реэкспорт.

**Ф2. Каркас контрактов.** `@u7-scl/domain/<m>/contract` создаётся как подпуть: реэкспорт того, что уже является контрактом (фасад, события, ошибки). Наполнение и стабилизация остаются на Фазу 4 [dmg-core-extract](../dmg-core-extract_20261020/spec.md) (Ф4, D-28).

**Ф3. Проверки в `arch:check`.**
- импорты между `domain/<m>` — только по `dependsOn`, без циклов;
- `@u7-scl/domain` не импортирует `ui`/`infra`/`apps` и пакеты `packages/<m>` (прикладной слой);
- `app`/`core` в домене допускаются только по allowlist долга;
- сверка маркеров `DEBT(<id>)` в коде, allowlist и `debt.md` (см. «Решения»).

**Ф4. Реестр долга и передача контекста.**
- `debt.md` в папке трека ведётся по ходу переноса. В нём группы: импорты `app`/`core` в домене, реэкспорты старых путей, `User` в `app`, прочее.
- В migration.md §2 строка трека ссылается на `debt.md`. В спеке и плане `golden-wish` добавляется блок «Входной долг»: какие записи из `debt.md` он обязан погасить для `wish`.
- Критерий закрытия записи — удаление маркера, allowlist и строки реэкспорта (проверяет Ф3).

**Ф5. Документация.** Раздел «Состояние переноса» в migration.md (какие модули перенесены), обновление legacy.md §6 про временные мосты, если затронуто.

## Нефункциональные требования

- Поведение не меняется: все существующие тесты проходят без правок логики (допустимы правки импортов).
- Никаких операций с `data/` (живые данные не затрагиваются).
- Гейт `bun run check` (lint, tsc, тесты, `arch:check`, `extract-check`) зелёный после каждого модуля.
- `dmg-core` не меняется (публичная поверхность — только через запись в треке `dmg-core-extract`).

## Критерии приёмки

1. Весь domain-код шести модулей и `dossier` лежит в `packages/domain/src/<m>/`, старые пути работают через реэкспорт.
2. `arch:check` содержит проверки Ф3 и зелёный; allowlist совпадает с `debt.md`.
3. `debt.md` полный: каждая запись имеет ID, место, причину, погашающий трек, критерий снятия.
4. Блок «Входной долг» есть в `golden-wish`, ссылка есть в `migration.md`.
5. `bun run check` зелёный, число тестов не уменьшилось.

## За рамками

- Перевод на Def, `Result`, Policy, UoW, `Timestamp` — `golden-wish` и дальше.
- Наполнение `contract` и очистка от `app`/`core` — по записям `debt.md`.
- Удаление реэкспортов и `legacy.md` — конец миграции.
- Миграция данных (`timestamp-data`).
