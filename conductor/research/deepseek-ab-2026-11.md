# A/B-тест исполнителей: DeepSeek против Claude (ноябрь 2026)

**Назначение:** технический отчёт эксперимента — постановка, обвязка, ход, ошибки и их следствия, данные, выводы. Рабочие правила, выведенные из него, — [deepseek.md](../architecture/deepseek.md).

> Дата: 2026-11-04. Трек `stream-dmg_20261103`, Фаза 2 (срез `student`: агрегат студента на Def, 8 UC, Job, UI бота). Итог фазы — в `archive/stream-dmg_20261103/summary.md`.

---

## 1. Цель

Недельный и 5-часовой лимиты Claude расходуются быстро, если всю работу ролей ведут Opus/Sonnet. Вопрос: можно ли отдать исполнителей (`test-designer`, `migrator`, `data-keeper`) DeepSeek через pi, оставив orchestrator и `tech-lead` на Opus, и чего это стоит по качеству и времени.

Критерии (по убыванию веса): качество, деньги/токены (доля исполнителей в общем расходе), скорость; дополнительно — число доработок и эскалаций, расход orchestrator'а на приёмку.

## 2. Постановка

- **Общая база.** Один коммит (`d616f12`) и один бриф `slices/student.md` (`tech-lead`, Opus, ~18 мин, 17.8M токенов, эквивалент $7.53). Стратегические вопросы С1–С4 решены до развилки.
- **Две ветки в отдельных worktree:** B — `ab/student-deepseek`, A — `ab/student-claude`. Порядок B → A: orchestrator не переносит в B знание из A (обратное искажение — orchestrator в A уже знал типовые эскалации; решения отдавались только в ответ на эскалацию, не заранее).
- **Одинаковые промпты шагов** (файлы промптов общие), одна схема доработок: дефект теста → `test-designer`, остальное → `migrator`, решения orchestrator'а — одинаковые в обеих ветках (например, barrel `@u7-scl/stream/domain` для скриптов до Ф3).
- **Модели.** B: `deepseek-flash` (thinking high); `deepseek-v4-pro` — на домене (оборван, см. §4) и на `data-keeper` для сравнения pro/flash. A: Sonnet 5.5 (модель ролей по умолчанию).
- **Слепое ревью.** Два `reviewer` на Opus, по одному на ветку; ветки — под ссылками `variant-1/2` (назначение случайное), `git log` запрещён (в сообщениях коммитов — имена моделей).
- **Цены.** DeepSeek — `usage.cost` pi. Claude — эквивалент по ценам API: Opus 5.5 $4/$20, Sonnet 5.5 $2/$10 за 1M (вход/выход), чтение кэша $0.20, запись — TTL 1 ч (×2 к входу). Для подписки это доля лимита, не деньги.

## 3. Обвязка и измерения

- **B:** pi в режиме `-p --mode json`, роль — `--append-system-prompt .pi/agents/<role>.md`, сессия на шаг (`--session-id`), суммирование `usage` по событиям `message_end` ассистента. Обёртка стала `scripts/pi-role.ts`.
- **A:** usage субагентов — из их JSONL-журналов (уникальные `message.id`), доработки через `SendMessage` — по окну времени.
- **Orchestrator:** usage основной сессии по окнам времени (B: до старта A; A: до конца A). Окно B включает отладку обвязки (§4).
- **Гейт:** после каждого шага orchestrator сам гонял тесты затронутых пакетов, в конце — `bun run check` и `test:bot`.

## 6. Результаты

| Метрика | B: DeepSeek | A: Claude |
|---|---|---|
| Исполнители, $ | **$2.09** (flash после исправлений), всего $34.29 | $24.52 (экв.) |
| Исполнители, токены | 143M (flash после исправлений), 98–99% кэш | 76M Sonnet, ≈97% кэш |
| Orchestrator (Opus) | 11.6M, $3.73 (с отладкой обвязки) | 8.6M, $2.62 |
| Доля исполнителей в расходе ветки | ≈36% $ (flash) | ≈90% $ |
| Время исполнителей | ≈130 мин | ≈76 мин |
| Круги доработок | 4 (25 дефектных тестов шага 1) | 3 (в основном `tsc`) |
| `check` / `test:bot` | зелёный, 3820 / 1012 | зелёный, 3964 / 1038 |
| Слепое ревью | **7/10**: 3 error, 6 warn, 6 info | **8/10**: 1 error, 7 warn, 7 info |

**Качество — что нашли ревьюеры.**
- B, `error`: кнопка «Записаться» осталась на роли `STUDENT` (enroll роль больше не выдаёт → активный студент видит кнопку); отказ по пререквизиту потерял название модуля; не снят `STUDENT_ROLE_MISMATCH`. Warn: фейк репозитория со своими выборками (риск ложно-зелёных тестов), правка фейка Ф1, события через `new EventDef` в обход `define`.
- A, `error`: не снят `STUDENT_ROLE_MISMATCH` (общий промах). Warn: правки за границами без эскалации (`runJob` в `platform/core`, экспорт в контракт), DCS/DQS объектами вместо классов, карточка прогресса без отставания, нет e2e 7b.
- Общие: скрипты переведены на barrel C-DEBT-3 (решение orchestrator'а), Т14 (`call-uc.ts`) не выполнен.

## 7. Выводы

1. **Экономия реальна, но на исполнителях.** Flash после исправления обвязки стоит ~$2 за фазу против ~$24.5 эквивалента Sonnet; лимит Claude при этом тратит только orchestrator (~9–12M Opus в обеих ветках).
2. **Качество ниже на шаг, и дефекты — в «смысловых» местах:** тесты нового среза (неверные фикстуры, вызов `Rule` как функции, недостижимые ожидания) и UI с сохраняемым поведением. Механические шаги по готовым тестам flash делает не хуже.
3. **Плохие тесты дорожают дважды:** автор эскалирует, orchestrator разбирает, `test-designer` чинит. Поэтому `test-designer` — на Claude.
4. **Обвязка важнее модели.** Одна настройка (`pi-dcp`) дала разницу в цене ×160 на шаге домена.
5. **Pro не окупился:** ×3.7 за ход, выводы те же.
6. **Часть промахов — постановка, не модель:** обе пропустили поручение «переписать legacy-публикации»; обе не сняли инвариант, который был в брифе одной строкой; неточный grep-критерий одна обошла молча, другая эскалировала.

## 8. Предложения

- Гибрид по таблице [deepseek.md](../architecture/deepseek.md) §2: flash — механика и доработки, Sonnet — `test-designer` и UI, Opus — orchestrator и ревью.
- Отключить `pi-dcp` и в интерактивном pi (`~/.pi/agent/settings.json`, `packages`) — он вредит кэшу и там.
- Бриф: поручения, которые выглядят как «правка старого», — отдельной строкой шага; grep-критерии — с явными исключениями (тесты, чужие модули).
- Роль `migrator`: правка вне «Границ» (`platform/*`, контракты) — всегда эскалация, даже «минимальная».
- Повторить замер на следующей фазе уже гибридом — проверить, что доля дефектов держится, а экономия сохраняется.

## 9. Ограничения

Одна фаза одного трека; B выполнялся первым (orchestrator учился на B); шаг домена B — два исполнителя (pro оборван, flash доделал); стоимость B «после исправлений» включает шаг 1 со сломанным кэшем лишь частично ($5.27 из $34.29 — до исправления); Claude — эквивалент по ценам API, а не реальные деньги; живых данных на машине разработки нет.
